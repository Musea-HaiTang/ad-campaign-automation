# 数据看板构建方法与样式说明

> 管什么：说明如何从零构建同类数据看板，包括需求拆解、数据契约、页面结构、状态管理、CSS 分层、交互、动画、防抖动和验收方法。  
> 不管什么：不记录具体活动、业务指标、批次规则或某张表的字段定义；这些内容属于业务文档。  
> 谁在什么时候读：准备新建数据看板、重做页面结构、统一视觉样式、加入交互动画，或排查页面抖动时读。

## 1. 这份文档解决什么问题

这份文档不回答“这个看板当前显示哪些数据”，而是回答：

1. 为什么页面要这样分区。
2. 数据、状态、页面和样式之间怎么衔接。
3. 怎样从需求一步步做出可维护的看板。
4. 怎样形成统一但不花哨的视觉风格。
5. 怎样做不引起页面抖动的交互和动画。
6. 怎样复现那种有质感的按钮按压反馈。

可以把整套方法概括成一句话：

> 先把用户要做的判断变成页面任务，再用稳定的数据契约和页面状态支撑它，最后用克制的样式与动画表达层级和反馈。

## 2. 总体设计原则

### 2.1 问题优先，图表其次

先写用户需要回答的问题，再决定页面、控件和图表。

错误顺序：

```text
先决定放大表格、折线图、饼图
再往里塞数据
```

正确顺序：

```text
用户要做什么判断
  ↓
完成判断需要哪些信息
  ↓
哪些信息适合表格，哪些适合图形
  ↓
最后决定视觉形式
```

### 2.2 一个页面只承担一组主要任务

一个页面可以同时有查看、筛选、对比和跳转，但不能让多个互不相干的任务争抢第一视觉层级。

页面至少要明确：

- 主任务是什么
- 次任务是什么
- 哪些功能放进弹窗
- 哪些信息只通过悬浮提示显示

### 2.3 数据是主角，装饰是配角

数据看板的第一目标不是“看起来丰富”，而是让人更快读到差异。

因此：

- 数据值比标签醒目
- 状态色只表达状态
- 装饰线、阴影和渐变保持克制
- 同类信息使用相同排版

### 2.4 先稳定，再好看

先保证列宽、容器高度、滚动位置和筛选状态稳定，再考虑动效。

如果基础布局会跳动，再漂亮的动画也会显得不可靠。

## 3. 推荐的整体架构

同类看板建议分成五层：

```text
数据源
  ↓
数据服务 / 数据契约
  ↓
页面状态
  ↓
渲染与交互
  ↓
样式与动画
```

### 3.1 数据源层

负责产生原始数据。

这一层可以是：

- 数据库
- 本地文件
- 第三方接口
- 定期快照

它不应该负责解释“页面怎么展示”。

### 3.2 数据服务层

负责把原始数据整理成稳定、可预期的 JSON。

这一层应完成：

- 统一日期格式
- 统一数值类型
- 聚合累计值
- 派生必要状态
- 标记不完整或异常数据
- 对缺失值给出明确结构

页面不应该反复猜数据含义，也不应该在多个地方重复计算同一指标。

### 3.3 页面状态层

页面只保存“用户当前选择”和“页面当前模式”。

例如：

```javascript
const state = {
  source: null,
  view: "overview",
  mode: "detail",
  filters: {},
  selection: null,
  metric: null,
  chart: null,
  expanded: [],
  overlay: null
}
```

状态变化后，只重新渲染受影响的区域。

### 3.4 渲染与交互层

负责：

- 根据状态生成 DOM
- 绑定点击、键盘和外部点击
- 保持焦点
- 保持滚动位置
- 只替换需要变化的内容

### 3.5 样式与动画层

负责：

- 视觉层级
- 响应式布局
- 控件状态
- 页面切换
- 按压、淡入、弹窗等短动画

动画不参与业务判断，也不能改变布局尺寸。

## 4. 从零构建的推荐顺序

### 第一步：写页面任务清单

先写出用户进入页面后要完成的动作：

```text
查看整体情况
切换分析视角
筛选数据
比较不同对象
查看明细
定位异常
执行下一步操作
```

每一项都要能对应页面上的某个区域或控件。

### 第二步：定义数据契约

数据契约先于页面代码。

至少要明确：

```text
对象 id
显示名称
时间字段
数值字段
状态字段
空值规则
是否完整
可用筛选项
```

建议先手写一份理想 JSON，再让服务端按它返回。

理想的页面数据应满足：

- 字段名稳定
- 类型稳定
- 缺失值明确
- 顺序稳定
- 不在前端拼业务口径

### 第三步：画低保真结构

先只画区域，不定颜色：

```text
┌──────────────────────────────────────────┐
│ 页面身份 / 全局切换 / 全局操作            │
├──────────────────────────────────────────┤
│ 当前视角 / 展示模式                       │
├──────────────────────────────────────────┤
│ 筛选区                                    │
├──────────────────────────────────────────┤
│ 概览区                                    │
├──────────────────────────────────────────┤
│ 主数据区：表格或图表                      │
└──────────────────────────────────────────┘

附加信息 → 通过按钮打开弹窗
```

结构成立后再进入高保真样式。

### 第四步：拆分页面组件

建议按职责拆：

```text
Header
ViewSwitcher
FilterBar
SummaryCards
DataTable
ChartArea
Dropdown
DatePicker
Modal
```

组件可以继续使用原生 HTML/CSS/JS，不必为了“组件”立刻引入框架。

### 第五步：建立单一状态源

所有筛选和模式都放进同一个状态对象：

```javascript
state.filters.start = "2026-10-01"
state.filters.end = "2026-10-07"
state.view = "detail"
renderAffectedAreas()
```

不要让各个 DOM 节点互相读取状态。

### 第六步：先完成静态渲染

先用固定数据把页面完整画出来：

- 表头
- 行高
- 列宽
- 空值
- 长文本
- 大数字
- 小屏幕

静态布局不稳定时，不要继续加交互。

### 第七步：接筛选和模式切换

每次切换都要问：

- 哪些区域需要更新
- 哪些区域应保持不变
- 当前焦点去哪里
- 当前滚动位置是否要保留

### 第八步：接图表或详细视图

图表只负责表达规律，精确读数仍应能在表格或提示中看到。

### 第九步：最后加入动画

先让页面“正确且稳定”，再让页面“有反馈”。

## 5. 页面结构怎么安排

### 5.1 页头

页头负责身份和全局操作：

```text
[当前对象 / 项目]
[上下文标签]
                        [概览入口] [次要操作] [主要操作]
```

原则：

- 最左侧是“我现在在哪里”
- 最右侧是“我能做什么”
- 全局操作不超过 3–4 个
- 按钮高度一致
- 图标按钮保持足够点击面积

### 5.2 视角切换

页面存在两种以上分析方式时，用分段控件，而不是隐藏在一级菜单里。

```text
[视角 A] [视角 B]
```

当前视角必须有清晰选中态。

### 5.3 展示模式

表格和图表回答的问题不同，建议互斥：

```text
[明细] [图表]
```

不要让图表插在表格上方，导致页面高度突然变化。

### 5.4 筛选区

筛选区只放会影响主数据的内容。

推荐顺序：

```text
时间范围
对象范围
其他筛选
结果数量 / 当前筛选摘要
```

筛选控件要：

- 共用高度
- 共用圆角
- 共用焦点态
- 文本可完整识别

### 5.5 概览区

概览区承担“先看结论”的作用。

建议 3–4 项，避免变成第二张表。

每项通常包含：

```text
标签
大数字
可选辅助说明
```

概览信息过多时，应移入弹窗。

### 5.6 主数据区

主数据区只承担一个核心任务：

```text
精确读数 → 表格
趋势和关系 → 图表
```

表格优先保证：

- 列宽稳定
- 对齐规则稳定
- 数字位数变化不挤动其他列

图表优先保证：

- 容器高度稳定
- 坐标轴可读
- 颜色数量受控
- 图例解释明确

### 5.7 次要信息进入弹窗

这些内容更适合弹窗：

- 某类对象的完整清单
- 对比信息
- 操作确认
- 低频辅助信息

弹窗不应抢走主页面主要任务。

## 6. 状态与渲染逻辑

### 6.1 单向更新

推荐流程：

```text
用户操作
  ↓
更新 state
  ↓
重新计算派生数据
  ↓
更新对应 DOM
```

不要：

```text
点击按钮
  ↓
直接读取多个 DOM 属性
  ↓
再让另一个 DOM 自己推断状态
```

### 6.2 局部刷新

表格筛选变化时：

- 更新筛选栏
- 更新概览
- 更新表格
- 不重建整个页面

图表类型变化时：

- 保留图表外层
- 只替换绘图内容
- 保留图表高度

### 6.3 浮层状态

页面存在多个下拉或日历时应统一管理：

- 同一时间只开一个
- 点击外部关闭
- `Esc` 关闭
- 关闭后焦点回到触发按钮
- 弹窗打开时避免焦点跑到遮罩后面

## 7. 样式系统

### 7.1 色彩

当前页面使用低饱和底色、中性文字和少量强调色：

```css
:root {
  --primary: #1D4ED8;
  --bg: #EDF1F6;
  --fg: #0F172A;
  --dim: #64748B;
  --border: #DCE5EF;
  --ok: #0F766E;
  --danger: #DC2626;
  --accent: #B45309;
}
```

颜色使用规则：

| 颜色 | 用途 |
|---|---|
| 主蓝 | 当前选中、主要操作、趋势线 |
| 深色 | 主要标题和数据 |
| 灰色 | 标签、说明、边框 |
| 深青 | 正常、完成、达标 |
| 红色 | 下降、错误、危险 |
| 琥珀 | 提醒、需要注意 |

不在同一个区域同时使用过多强调色。

### 7.2 字体

页面正文：

```css
font-family:
  "Segoe UI",
  "Microsoft YaHei",
  system-ui,
  sans-serif;
```

数据数字：

```css
font-family:
  "Cascadia Mono",
  Consolas,
  ui-monospace,
  monospace;

font-variant-numeric: tabular-nums;
```

字体角色：

| 角色 | 规则 |
|---|---|
| 页面标题 | 较大、600 字重 |
| 区块标题 | 小号、600 字重 |
| 正文 | 系统字体，保持清晰 |
| 表头 | 更小、弱色、宽字距 |
| 数据 | 等宽、稳定列宽 |

同一页面不要混用太多字体系列。

### 7.3 布局与宽度

推荐视觉宽度：

```css
.page {
  max-width: 1180px;
  margin: 0 auto;
  padding: 0 24px;
}
```

理由：

- 常见桌面屏幕下阅读距离合适
- 表格不会无限拉长
- 顶部操作仍在视野内

### 7.4 间距

统一使用一套间距尺度：

```text
4px   紧凑元素内部
6px   小图标与文字
8px   卡片内控件
10px  同一组按钮
12–16px 区块内部
22px  页面大区块之间
```

不要每个组件单独写随手数值。

### 7.5 圆角和阴影

当前风格使用：

```text
控件圆角：8–10px
卡片圆角：12px
弹窗圆角：14px
```

阴影只用于表达层级：

- 普通卡片：极轻阴影或仅细边框
- 浮层：中等阴影
- 弹窗：较深阴影

不要给所有元素加阴影。

### 7.6 表格样式

推荐规则：

- `table-layout: fixed`
- 表头弱化
- 数字使用等宽字体
- 数值列居中或右对齐，全表保持一致
- 行悬停只改变背景和强调线
- 不通过加粗所有单元格制造层级

### 7.7 空状态

空状态要说明接下来能做什么，而不是只写“暂无数据”。

推荐：

```text
当前筛选下没有可展示的数据
调整筛选条件后再试
```

## 8. CSS 文件怎么分层

建议按以下顺序组织：

```text
1. 设计变量
2. 基础重置
3. 排版
4. 通用按钮和控件
5. 页面布局
6. 业务数据展示样式
7. 浮层和弹窗
8. 动画和媒体查询
9. 减少动态效果
```

示例：

```css
/* tokens */
:root { ... }

/* base */
* { box-sizing: border-box; }
body { ... }

/* shared controls */
.button { ... }
.dropdown { ... }

/* layout */
.page { ... }
.section { ... }

/* data */
.summary { ... }
.table { ... }

/* overlays */
.modal { ... }

/* motion */
@keyframes fade-in { ... }

@media (prefers-reduced-motion: reduce) { ... }
```

这样调整颜色、控件、页面或动画时，不需要在文件里来回寻找。

## 9. 防抖动

页面抖动通常不是动画本身造成的，而是动画过程中改变了布局。

### 9.1 固定列宽

```css
table {
  table-layout: fixed;
}
```

数字变化不会改变列宽。

### 9.2 固定容器高度

图表、轮播、模式切换区域应固定高度。

```css
.chart-area {
  height: 414px;
}
```

### 9.3 只更新内容，不重建外壳

切换图表时保留外层容器，只替换内部绘图。

### 9.4 行展开保持锚点

展开前记录目标行的屏幕位置；重绘后校正滚动，使该行仍在原位置。

### 9.5 浮层脱离文档流

下拉和日历使用：

```css
position: absolute;
```

打开时不能把下方内容推走。

### 9.6 不要动画布局属性

避免动画：

```text
width
height
top
left
margin
padding
```

优先动画：

```text
transform
opacity
background-color
border-color
box-shadow
```

## 10. 动画系统

### 10.1 动画层级

建议只保留三档：

| 层级 | 用途 | 时长 |
|---|---|---:|
| 反馈 | 按钮按压 | 100ms |
| 内容 | 下拉、图表、列表内容切换 | 140–160ms |
| 浮层 | 弹窗和遮罩 | 130–170ms |

统一缓动：

```css
cubic-bezier(.2, .8, .2, 1)
```

### 10.2 按压反馈

这是整套交互里最值得保留的细节。

```css
.action-button {
  transition:
    border-color .16s ease,
    background-color .16s ease,
    color .16s ease,
    transform .1s ease;
}

.action-button:active:not(:disabled) {
  transform: translateY(1px) scale(.985);
}
```

为什么有质感：

1. 只在真正按下时触发。
2. 位移只有 `1px`。
3. 缩放到 `98.5%`。
4. 时长只有 `100ms`。
5. 同时伴随颜色和边框变化。
6. 不弹跳、不回弹、不做夸张缩放。

这属于微交互中的：

```text
Microinteraction
Press feedback
Tactile feedback
```

### 10.3 下拉动画

```css
.dropdown-panel {
  transform-origin: 50% 0;
  animation: dropdown-in .14s cubic-bezier(.2, .8, .2, 1);
}

@keyframes dropdown-in {
  from {
    opacity: 0;
    transform: translateY(-3px) scale(.99);
  }
  to {
    opacity: 1;
    transform: translateY(0) scale(1);
  }
}
```

### 10.4 内容切换动画

```css
@keyframes content-in {
  from {
    opacity: 0;
    transform: translateY(2px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

只对内容层做透明度和 `2px` 位移，不改变容器大小。

### 10.5 弹窗动画

```text
遮罩：淡入
内容：淡入 + 向上 5px + 轻微缩放
关闭：反向淡出
```

### 10.6 减少动态效果

必须支持系统设置：

```css
@media (prefers-reduced-motion: reduce) {
  .action-button,
  .dropdown-panel,
  .modal,
  .modal-box,
  .content {
    animation: none;
    transition: none;
  }
}
```

## 11. 可访问性与键盘操作

至少保证：

- 所有可点击元素使用 `button` 或正确角色
- 有清晰 `:focus-visible`
- `Esc` 能关闭下拉、日历和弹窗
- 下拉支持键盘选择
- 弹窗关闭后焦点回到触发按钮
- 不仅靠颜色表达状态
- 文本缩放到 125% 时布局仍可用

## 12. 响应式原则

桌面优先的看板也要处理窄屏：

```text
桌面：完整表格或多列卡片
平板：减少列数或允许横向滚动
手机：单列摘要、卡片化、减少图例
```

响应式不是简单缩小所有字体，而是重新安排信息优先级。

## 13. 当前实现的推荐文件职责

这套方法在当前项目中的落地位置：

| 职责 | 文件 |
|---|---|
| 页面骨架 | `web/static/index.html` |
| 状态、渲染、交互 | `web/static/app.js` |
| 设计变量、布局、组件、动画 | `web/static/app.css` |
| 数据整理与接口契约 | `automation/scripts/workspace_payload.py` |
| 本地接口与静态服务 | `web/app.py` |
| 使用说明 | `web/README.md` |

职责边界：

- 数据层不输出 HTML
- 页面层不重复计算业务口径
- 样式层不决定数据含义
- 动画层不改变布局尺寸

## 14. 验收清单

### 结构

- 页面主任务是否清晰
- 全局操作是否不超过必要数量
- 次要信息是否已移入弹窗
- 同类控件是否使用相同尺寸

### 数据

- 空值是否有明确表现
- 长文本是否完整
- 大数字是否不撑破列宽
- 无数据时是否有行动指引

### 稳定性

- 切筛选时滚动位置是否合理
- 切图表时容器高度是否变化
- 展开行后点击行是否保持原位
- 打开浮层是否推动页面内容

### 动画

- 按压是否有即时反馈
- 动画是否短于 200ms
- 是否只动画 `transform` 和 `opacity`
- 是否关闭了布局属性动画
- 是否支持减少动态效果

### 可访问性

- 键盘能否完成主要操作
- 焦点是否可见
- `Esc` 是否能关闭浮层
- 颜色是否是唯一状态提示

## 15. 最终模板

以后再构建同类网站，可以直接按这个骨架开始：

```text
1. 写任务清单
2. 定义数据契约
3. 画低保真结构
4. 建立单状态对象
5. 完成静态页面
6. 接筛选和模式切换
7. 固定表格列宽与图表高度
8. 统一色彩、字体、间距和控件
9. 加入局部刷新
10. 加入按压、淡入、弹窗动画
11. 支持键盘与减少动态效果
12. 用真实规模数据验收
```

最重要的不是复用某个 CSS 值，而是复用这套决策顺序：

> 任务决定结构，结构决定组件，组件决定样式，交互只改变必要区域，动画只表达状态。
