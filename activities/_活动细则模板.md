# {活动名} · 活动细则

> **管什么**：本活动长期稳定的事实、用户明确给出的约束、命名与投放位置、落地链接绑定和文案输入入口。
> **不管什么**：通用流程 → `ad_output/流程文档/CSDN广告投放自动化流程.md`；活动启停 → `automation/docs/activity_state.md`；批次、指标、圈选统计和复盘记录 → 数据库。
> **谁什么时候读**：摸产品后填写；写关键词、写文案、生成 YAML 和复盘前读取。

## 填写纪律

- 只写现在仍然成立的**活动专属事实**。当前活动状态、当前批次、任务 ID、曝光、点击、圈选数字和复盘结论不写进本文件。
- 数据库 `activities/_db/投放数据.db` 是运行记录的唯一真相。本文件与数据库冲突时，以数据库为准。
- 产品事实必须写来源和核查日期；没有核到、用户没有明确给出或已经过期的内容写“待确认”，AI 不得自行推测。
- 客户邀请链接、账号和个人业务数据只留在当前活动目录，不得复制到示例活动或 GitHub 发布包。

### 最低填写门槛

| 阶段 | 必须已经填好 |
|---|---|
| 做物料前 | §0 活动身份与类型、§1 定位、§2 产品事实、§3 用户特例与链接、§4 命名与投放位置、§6 文案输入 |
| 生成整活动 YAML 前 | 用户已确认物料；本次要建的每个桶已有明确落地链接；§2 没有影响文案的“待确认”项 |
| 首次复盘后 | 只补 §5 中以后仍成立的稳定结论，不复制本次指标、批次或复盘正文 |
