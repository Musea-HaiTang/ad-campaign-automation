# 验证数据（彩排借用对象 · 只取名字，不要创建）

这里只干一件事：**做彩排时可以借用的后台已有对象名单** —— `配置/借用对象.yaml`
（**21 个资源名 = 7 组 × 3** + **7 份分发名单名**）。

**不写关键词、不写文案**：关键词和文案是每个活动自己的真实内容，彩排要验的是「后台能不能按名字选中」，
跟用哪些词无关。这份清单也不含任务组 / 子业务线，那些见下面「固定项」。

## 怎么用（用的时候取）

1. 给要做彩排的活动写好真实内容（分桶 / 关键词 / 文案）——照常走产出侧流程。
2. 从 `配置/借用对象.yaml` 里**取名字**，抄进那个活动的 `配置/活动定义.yaml`：
   - `audiences[].abGroups[].resource` ← 资源组里的名字（一组 3 个直接抄；也可以混着挑，只要在清单里）
   - `audiences[].distributionList` ← 分发名单名
3. 跑执行层四步（dry-run），命令见下。

## 固定项（不用改，也不是从清单里取）

| 项 | 值 |
|---|---|
| 任务组 | `华为云码道-博客T0`（沿用已有，不新建） |
| 子业务线 | `训练营与大赛` |
| 渠道 / 计费价格 / 曝光上限 | `PC-博客-详情页-相关推荐T0` / `20`（**彩排用，不为准**——正式 YAML 的计费价格每轮问用户，见 `automation/campaigns/README.md`）/ `100000 · 500000 · 500000` |
| 投放日期 | 用**运行当月**（后台日历按当月天数点），如 `2026-09-15 ~ 2026-09-20`、时段 8–23 点 |

## 规矩

1. **永远不要加 `--submit`**：这里借的是别人后台已有的对象，一提交就会多出垃圾资源 / 客群 / 工单。
2. **名字一字不差**：后台是「完全相等 → 前缀匹配」，多一个空格、少一个字都选不中（这份清单 2026-09-11 逐条核对过）。
3. 彩排产物（截图 / 断点账本）落在**各活动自己的** `日志/`，已被 git 忽略。
4. 重跑加 `--reset-progress`（彩排也一样会往账本写 `done`——步骤失败也照写，这个假通过问题还没修）。

## 常用命令（`<活动>` = `activities/火山Interact`，yaml 名换成该活动的）

```powershell
.venv\Scripts\python.exe -u automation/scripts/run_taskgroup.py --config <活动>/配置/<前缀>.yaml
.venv\Scripts\python.exe -u automation/scripts/run_ads.py       --config <活动>/配置/<前缀>.yaml
.venv\Scripts\python.exe -u automation/scripts/run_audience.py  --config <活动>/配置/<前缀>.yaml
.venv\Scripts\python.exe -u automation/scripts/run_taskorder.py --config <活动>/配置/<前缀>.yaml
```

改了活动定义后重新生成物料 / 整活动 YAML：
```powershell
.venv\Scripts\python.exe -u ad_output/工具/gen_material.py --def <活动>/配置/活动定义.yaml
.venv\Scripts\python.exe -u ad_output/工具/gen_yaml.py     --def <活动>/配置/活动定义.yaml
```
