## 口径

- 数据来自后台的**只读查询接口**（任务列表 + 任务资源明细），**以后台为准**。
- **假期（含周末）数据会更少**（用户 2026-09-28 说明）：看这段的**绝对曝光**时要知道这个背景，
  别把假期里的低曝光直接当成投放出了问题。`-6` 批（9/24 起）的观察窗里
  **9/25 中秋 + 9/26~9/27 周末**都在，后面 **10/1 起又是国庆假期**，本活动剩余投放期大部分在假期里。
- **按天事实**：一天一行，只含有数据出现的日期；**昨天及以前是终值，今天还没走完**
  （看板把末尾那天标出来，"日均曝光"等判定按**完整日**算）。
- **资源级**：一个资源一行，是**累计值**——覆盖该任务整个投放期到取数这一刻，所以含当天。
  想看"某段时间里三套文案各涨了多少"，拿两条读数做差。库里读数的起点 = 建库那天（2026-09-20），
  更早的读数在 `2026-09-16_1006` 那几份旧快照的 `资源级累计.csv` 里。
- 取数时刻和标签在**文件夹名**里（`2026-09-20_0939`、`2026-09-20_1430_调整前`）。
  一天取几次就有几个文件夹——**它们是流水，不等于"最新一份才是真相"**
  **「刷新今天」不落流水**（数据直接进台账库，`--no-archive`），所以一天最多一份流水 = 当天的「取数」（2026-09-20 起）。
  （2026-09-20 之前的老设计是"最新快照即真相"，窄区间取数会把看板区间缩窄，已废弃）。
- `测试工单-火山引擎MediaKit-hang-A类…` 是 A 组的**正式口径**（正版 A 组时间设错、2026-09-14 后已无数据）：
  **分析 A 组只看这一条**（2026-09-17 用户定）；9/14 那天两条并存、数据混杂，不当基线用。
