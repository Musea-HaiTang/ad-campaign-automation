# 部署故障排查

> **管什么**：AI 部署阶段的网络、Python、venv、pip、测试和看板启动问题。
> **不管什么**：业务脚本参数和投放异常；分别看执行层文档与业务 SOP。
> **谁什么时候读**：`setup_ai.py` 返回失败、结果不是 `ok`，或部署后看板无法访问时。

## 先看这三个文件

```text
.local/setup-ai.log
.local/setup-result.json
.local/test-results.json
```

不要先手工修环境或补写结果文件。先确认失败命令、退出码和失败阶段。

## GitHub 下载失败

如果 `git clone` 超时或被代理阻断，改用 codeload 下载对应分支或提交的 ZIP。下载后确认项目根目录就是工作空间根目录。

## 找不到 Python

- 确认当前 AI 宿主能调用 Python 3.12-3.14
- 不要使用 WindowsApps 的 `python.exe` 占位别名
- 如果存在多个解释器，使用真实可执行的 Python 启动 `scripts/setup_ai.py`

## venv 没有 pip

`setup_ai.py` 会依次尝试：

1. venv 内 `python -m pip`
2. `python -m ensurepip --upgrade`
3. 系统 Python 的 `pip --python <venv解释器> install pip`

如果三者都失败，查看 `setup-ai.log`。不要手工删除整个 venv 或数据库。

## 测试失败

WorkBuddy 存在批量删除保护时，测试会自动按文件运行。AI 应读取 `.local/test-results.json`：

- `status: ok`：测试通过
- `status: failed`：查看 `results[].failures` 和 `output`

不要为通过测试而关闭安全保护或改动业务断言。

## 看板启动失败

部署脚本通过 `web/start-hidden.vbs` 启动看板，并通过 `/api/health` 验收。

可只读检查：

```powershell
.venv\Scripts\python.exe automation\scripts\board_service.py --status
.venv\Scripts\python.exe automation\scripts\board_service.py --url
```

若首选端口被占用，脚本会使用实际端口，不能只检查固定 URL。

如果部署命令能通过看板健康检查，但命令结束后进程被宿主回收，当前环境无法让
`--start-board` 保持常驻。此时请让用户双击 `web/start-hidden.vbs`，再检查
`board_service.py --status`；不要把“启动过”当作“仍在运行”。

## CSDN 登录失败

登录不是无人值守步骤。AI 应打开网站并请用户本人操作，完成后重新运行：

```powershell
.venv\Scripts\python.exe scripts\doctor.py
```

失败时不得使用其他账号、绕过验证码或读取用户凭据。
