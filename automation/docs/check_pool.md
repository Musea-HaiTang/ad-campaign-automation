# 想法池自检 `check_pool.py`（离线，建批前后都能跑）

> **管什么**：想法池的验证位结构、文案行 ↔ 已建批次是否一致——只读、秒级、不开浏览器、不改任何文件。
> **不管什么**：批次配置本身填得对不对（→ [`check_batch_plan.md`](check_batch_plan.md)）、后台对象在不在（→ [`check_campaign.md`](check_campaign.md)）。
> **谁什么时候读**：建批取文案前、建批收尾回写池子后，各跑一次。

## 怎么跑

```powershell
.venv\Scripts\python.exe -u automation/scripts/check_pool.py            # 全活动
.venv\Scripts\python.exe -u automation/scripts/check_pool.py --only KIRO # 只看一个活动
```

退出码：**0 = 池子结构与批次一致；1 = 有问题（只报，不动文件）**。

## 它查什么（为什么有它）

**2026-10-16 真踩到的**：池子里那个「在跑」标记是从**角度**那一维贴的，读的人却按**文案**读——

- KIRO D 桶 `D2-b/D4-b/D5-b` 标着「在跑」，可 D `-6` 建的是**同角度的直给版**（D2/D4/D5）；
  这三行是 10-15 那次"四种风格重写"（commit `90d3a4b`）才写出来的，**从没上过**；
- KIRO C 桶 `C9-b` 标「在跑」，C `-9` 最后选的是 C10/C6-b/C2-b，**根本没建它**；
- 腾讯云 TokenHub `T-11-b` / `T-05-b` 同日被这条自检抓出来，同样是假在跑。

⛔ **同日用户定：池子不再写「在跑」那一行**（原话：「**待验证想法池就别加那一行在跑了呗，要看在跑就看那一批次的记录就好了呀。不然老是出现错误。**」）——
池子**只放"还没上过的"**；哪批在跑，去看数据库 v2 的 `bucket_batch` / `creative`，人工判断过程看 `物料/复盘/复盘-*.md`。
所以下表 ① 只对**历史遗留的行级标记**有效（现在的池子已经没有这种标记了）。

根因是**两套编号之间没有对照**：后台资源名（`…D类 · 对照-6`）与池子行号（`D2-b`）各写各的，
错位的行能一直躺着。所以这条自检拿**已建批次的文案标题**去对池子的行：

| 查什么 | 说明 |
|---|---|
| ① **假在跑**（**已停用**） | 只在池子里还残留行级 `**在跑**` 标记时才命中；2026-10-16 起池子不再写这一行 |
| ② **该删没删** | 这条文案**已经在某批里建过** → 池子只放"还没上过的"，该删 |
| ③ **存量提示** | 各桶还没上过的文案条数；**≤5 条**时按口径该轮到“全桶统一补货”的补货线 |
| ④ **验证位结构** | 未投角度必须有且只有 1 条 `**首测**` + 1 条 `**补验**`；补验必须是 `对仗 / 化用 / 借鉴诗词`，额外文案必须标 `**备选**`。一条已投掉后，允许单条残组等待复盘 |

## 口径（写进脚本的五条约定）

1. **池子不写「在跑」那一行**（2026-10-16 用户定）：哪批在跑去看批次 YAML / 复盘报告。
   脚本里保留的 `**在跑**` 判定**只用于历史遗留的行级标记**（2026-10-16 第一次跑就因说明文字里出现"在跑"两个字误报了 D2-b/D4-b）。
2. **池子只放"还没上过的"**：建完批就回写——上了线的行**直接删**（⛔ 不再另写"在跑"那一行）。
3. 多产品活动的池子**一个产品一份、表里没有「桶」列** → 存量按文件名分组。
4. 池子按角度块分表，每个角度块下面再放文案表；脚本把**每条文案行**当池子条目读，角度块本身不单独算一条存量。
5. **验证位渐进迁移**：同一角度下只要有一条文案标了 `首测` 或 `补验`，就启用结构检查；没标记的文案按 legacy 跳过。下一次补货、取第二份文案或修改时，该角度下的文案必须补验证位标记；旧池第二份候选若不合格，不能自动充当补验。

## 已知边界

- 只比**标题**（池子行里 `标题：\`…\`` ↔ 批次的 `resources[].title`）：同一个标题被两条池子行复用时认不出来——
  标题本来就是唯一的那句话，复用即错，先不做模糊匹配。
- 池子**不再有"在跑"那一行**（2026-10-16 起）；脚本只核表格里的行。
