# 登录与运行验收

> **管什么**：部署后的后台看板检查、CSDN 双站人工登录和最终环境诊断。
> **不管什么**：安装依赖、创建 venv 和数据库初始化；那些属于部署阶段。
> **谁什么时候读**：部署脚本返回成功后，或需要重新登录、检查运行环境时。

## 1. 确认后台看板

从 `.local/setup-result.json` 读取 `board.url`。如果没有记录，可在项目根目录执行：

```powershell
.venv\Scripts\python.exe -m automation.scripts board-service --url
```

macOS 对应命令：

```bash
.venv/bin/python -m automation.scripts board-service --url
```

AI 只检查健康接口并记录实际地址，**不自动打开看板页面**。端口以 `board-service --url` 的实际输出为准。

## 2. 由用户完成 CSDN 登录

启动浏览器前，AI 必须先说明接下来会同时打开以下两个网站，并等待用户回复已准备好：

- CSDN 广告后台
- `data.csdn.net` 数据平台

登录必须由用户本人完成，AI 不得索要账号、验证码或代替用户扫码。

需要启动项目公共浏览器进行登录时，AI 可执行：

```powershell
.venv\Scripts\python.exe scripts\doctor.py --login
```

macOS 将解释器替换为 `.venv/bin/python`。

该命令会先打印登录说明，再同时打开两个站点，等待两个登录态恢复。两个站点可以由用户任意顺序完成登录。

## 3. 最终诊断

用户确认登录完成后执行：

```powershell
.venv\Scripts\python.exe scripts\doctor.py
```

macOS 将解释器替换为 `.venv/bin/python`。

验收通过时，Python、依赖、浏览器、端口、数据库、owner 和两个 CSDN 站点都应显示 PASS。

## 4. 脚本彩排

最终诊断通过后，用示例活动验证资源与任务工单脚本能在本机正常操作后台：

```powershell
.venv\Scripts\python.exe scripts\doctor.py --rehearsal
```

macOS 将解释器替换为 `.venv/bin/python`。

脚本固定读取
[`rehearsal-腾讯云产品-hang.yaml`](../../activities/_示例活动/配置/rehearsal-腾讯云产品-hang.yaml)，
依次执行：

1. `check-batch-plan`
2. `run-ads --headed --reset-progress`
3. `run-taskorder --headed --reset-progress`

两条 `run-*` 命令都必须是 dry-run。彩排会打开广告后台、填写资源和任务工单表单、回读并截图，然后取消；
**不提交，不新增、不修改、不删除任何后台对象**。示例 YAML 使用的任务组和资源仅用于搜索、选择和验证表单。
`--reset-progress` 只重置示例活动的彩排断点，确保每次验收都会实际执行，而不是跳过旧的 dry-run 记录。

打开浏览器前，AI 必须先原样说明这是一次不提交的彩排，并等待用户明确回复开始。命令自身也会要求输入
`开始彩排`；未输入该确认词时不会执行任何彩排子命令。

通过条件是三条子命令均返回 `RESULT: OK`，最终显示 `REHEARSAL: OK` 和 `DOCTOR: OK`。

## 部署完成标准

- `.local/setup-result.json` 为 `ok`
- `.local/test-results.json` 为 `ok`
- 看板在后台运行且健康接口正常
- 用户已登录 CSDN 广告后台和 `data.csdn.net`
- `doctor.py` 返回成功
- 用户确认后完成彩排，`doctor.py --rehearsal` 返回成功

未完成登录时，可以说明“安装与测试已完成，等待用户登录”，但不能宣称整个项目已经完全可用。

全部通过后，AI 只提示看板已在后台运行、需要时可访问实际地址，并告诉用户以后发送 `进行这个活动：<活动链接>` 开始工作。
