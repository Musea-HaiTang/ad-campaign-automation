# AI 部署说明

> **管什么**：从独立工作空间获取项目、运行 AI 一键部署、检查结果和处理部署阶段异常。
> **不管什么**：日常投放业务、看板使用和复盘规则；分别看业务 SOP 与运营使用说明。
> **谁什么时候读**：第一次部署、更换电脑、重新部署或需要确认部署是否真正成功时。

## 前置条件

- Windows 10/11
- 独立工作空间；项目根目录就是该工作空间，不能再套一层旧项目
- Python 3.12-3.14，可由当前 AI 宿主调用
- Microsoft Edge 或 Google Chrome
- 可访问 GitHub 或 codeload、PyPI 和 CSDN

AI 获取仓库时可根据网络情况选择 `git clone` 或 codeload 下载。GitHub 直连失败不是项目缺陷，AI 应继续尝试可用的下载方式。

## 唯一部署命令

AI 必须先询问并确认真实 `owner`，然后在项目根目录执行：

```powershell
python scripts/setup_ai.py --owner "真实owner" --run-tests --start-board
```

不得使用文档示例值、操作系统用户名或旧操作者的 owner 代替。

## 脚本会做什么

1. 检查 Python 并创建或复用 `.venv`
2. 检测 pip；缺失时尝试 `ensurepip` 和系统 pip 修复
3. 安装 `requirements.txt`
4. 检测 Edge 或 Chrome
5. 创建运行目录和本机配置
6. 初始化或复用数据库
7. 初始化空库示例活动
8. 运行自动化测试
9. 通过 `web/start-hidden.vbs` 启动常驻看板
10. 检查看板 `/api/health`
11. 写入部署和测试结果

## 结果文件

```text
.local/setup-result.json
.local/test-results.json
.local/setup-ai.log
```

部署成功的判断标准：

- `setup-result.json` 的 `status` 为 `"ok"`
- `test-results.json` 的 `status` 为 `"ok"`
- `setup-result.json` 中存在看板 URL
- 看板健康接口返回本项目服务
- 日志中没有未处理的异常

不得手工补写结果文件冒充成功。

## 数据和重复部署

- 已有 `activities/_db/投放数据.db` 时保留原数据，不重新写入示例
- 已有合法 `.local/operator.json` 时复用原 owner
- `.browser-profile/` 中的登录态不由部署脚本删除
- 重复部署是幂等操作，不应覆盖已有数据库

## 失败时

部署脚本会写入失败结果并保留日志。AI 应停止，不得自动切换到手工安装步骤。需要提供：

```text
.local/setup-ai.log
.local/setup-result.json
```

继续排查见[故障排查](故障排查.md)。

部署成功后的登录和运行验收见[登录与验收](登录与验收.md)。
