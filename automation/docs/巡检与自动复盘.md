# 巡检与自动复盘

> **管什么**：供应商无关的定时巡检命令、报告格式、待复盘队列和 Codex / WorkBuddy / 人工接入方式。
> **不管什么**：复盘正文排版 → [`复盘会话格式.md`](复盘会话格式.md)；判定实现 → [`judge_batch.md`](judge_batch.md)；取数实现 → [`fetch_perf.md`](fetch_perf.md)。
> **谁什么时候读**：配置自动巡检、换成不同 AI 产品运行、排查巡检没有执行或通知时。

## 1. 核心原则

巡检逻辑只维护一份，不把 Codex 或 WorkBuddy 的提示词写成两套业务规则。

```text
运行 patrol.py
→ 刷新今天数据并等待完成
→ 运行数据库判定并标记待复盘
→ 输出待复盘队列
→ 写巡检报告
→ 平台负责转发通知和创建复盘会话
```

核心命令：

```powershell
.venv\Scripts\python.exe automation/scripts/patrol.py
```

退出码：

| 退出码 | 最后一行 | 含义 |
|---|---|---|
| `0` | `PATROL: OK` | 取数成功，当前无需复盘 |
| `0` | `PATROL: DUE` | 取数成功，有待复盘项 |
| `1` | `PATROL: FAILED` | 看板不可用、取数失败或判定失败 |

报告自动写入 `automation/_tmp/patrol/{时间}.md`，同时输出到标准输出。

## 2. 运行前提

- 看板服务必须正在运行；
- 看板负责公共浏览器取数，巡检脚本不自己开浏览器；
- 数据库默认是 `activities/_db/投放数据.db`；
- 如果取数有失败项，本轮停止，不拿不完整数据做判定；
- 已收尾活动不参与整批取数，判定也会跳过。

## 3. 平台接入模板

以下字段由运营在所用 AI 产品的定时任务里设置：

```text
任务名称：ad-management-patrol
工作目录：<独立工作空间中的项目根目录>
运行时间：<按运营工作时段填写>
执行命令：.venv\Scripts\python.exe automation/scripts/patrol.py
成功通知：转发标准输出中的巡检报告
失败通知：转发标准错误和 PATROL: FAILED
复盘会话：仅当 PATROL: DUE 时创建或复用复盘会话
```

项目不依赖某个固定时间、固定任务名、固定 thread ID 或固定 AI 产品。

### 3.1 Codex

在 Codex 的 Scheduled Tasks 中创建一个定时任务，工作目录设为本仓库，定时执行上面的核心命令。

任务提示只写执行与转述要求：

```text
在项目根目录运行：
.venv\Scripts\python.exe automation/scripts/patrol.py

原样转述标准输出中的巡检报告，不要自行重算指标。
如果最后一行是 PATROL: FAILED，只报告失败，不创建复盘会话。
如果最后一行是 PATROL: DUE，把本次全部待复盘项合并到一个复盘会话。
如果当前 Codex 环境提供会话 ID，用 review_queue.py assign 写回；
没有稳定会话 ID 时保持 thread_id 为空，不得伪造。
```

### 3.2 WorkBuddy

在 WorkBuddy 的定时任务、自动化或等效调度入口中，填写同一份接入模板和同一条核心命令。

WorkBuddy 5.9.3 实测：

- 自动任务默认使用 Git Bash，命令路径必须写成正斜杠；
- 当前会话 ID 通过 `CODEBUDDY_SESSION_ID` 注入；
- `CLAUDE_SESSION_ID` 同时可用且值相同；
- `${CODEBUDDY_SESSION_ID}` 不会在任务提示词里自动替换，不能依赖该写法。

因此 WorkBuddy 使用：

```bash
.venv/Scripts/python.exe automation/scripts/patrol.py
```

`patrol.py` 会自动读取 `CODEBUDDY_SESSION_ID`，把本轮所有 `thread_id` 为空的待复盘项写回当前会话；已有 `thread_id` 的项不覆盖。

需要人工修复绑定时，才执行：

```bash
.venv/Scripts/python.exe automation/scripts/review_queue.py \
  --db activities/_db/投放数据.db \
  assign <review_id> <workbuddy_conversation_id>
```

如果平台只支持通知、不支持自动创建会话，则：

- 正常发送巡检报告；
- 保持 `review.thread_id` 为空；
- 运营人工进入复盘流程；
- 不得为了填字段伪造 ID。

### 3.3 人工或其他平台

人工运行时只需：

```powershell
.venv\Scripts\python.exe automation/scripts/patrol.py
```

也可以交给 Windows 任务计划程序，让它在工作目录为本仓库时执行同一命令。

## 4. 判定后处理

查看待复盘队列：

```powershell
.venv\Scripts\python.exe automation/scripts/review_queue.py `
  --db activities/_db/投放数据.db list
```

`patrol.py` 已经执行 `judge_batch.py --mark --brief`，不会重复创建 review。

复盘会话要求：

- 一轮最多新建一条普通复盘会话；
- 本轮全部待复盘桶放在同一条会话；
- 已有 `thread_id` 的 review 继续在原会话处理；
- 只有平台确实提供会话 ID 时才执行 `assign`；
- 复盘正文按 [`复盘会话格式.md`](复盘会话格式.md)。

## 5. 通知格式

平台转发脚本输出即可，不得让模型重算指标。报告至少包含：

```text
# 巡检报告
## 取数
模式 / 完成数 / 失败数

## 判定
judge_batch --mark --brief 的标准输出

## 待复盘
review_queue list 的结构化结果
```

有失败时不做“无复盘”结论，只报告本轮失败。

## 6. 数据与边界

- 巡检只读后台数据并写数据库；
- 巡检不创建、修改、删除 CSDN 后台对象；
- 巡检不审核、不提交、不下线；
- 巡检不建 issue、不改代码、不提交、不推送；
- 公共浏览器由看板服务统一使用；
- DeepSeek 或其他搜索工具不是巡检依赖。

## 7. 常见故障

| 现象 | 检查 |
|---|---|
| `PATROL: FAILED`，看板不可用 | 运行 `board_service.py --status` 查看实际地址 |
| 数据未刷新 | 看板取数状态、公共浏览器登录态 |
| 到门槛但没有待复盘 | 查看判定输出和 `review.status` |
| 重复创建复盘会话 | 先查 `review_queue.py list` 中的 `thread_id` |
| 平台没有会话 ID | 保持 `thread_id` 为空，走人工复盘 |
