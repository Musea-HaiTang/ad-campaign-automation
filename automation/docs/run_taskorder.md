# 建任务工单 · `run_taskorder.py`（执行层第 4 步）

> **管什么**：这个脚本怎么跑、在后台点哪些控件、只有它才会踩的坑。
> **不管什么**：`taskOrder` 字段怎么填 → [`../campaigns/README.md`](../campaigns/README.md) §taskOrder（含「AB 组三条硬规则」与单资源长期单）；排队 / 断点 / 止损 / 回读口径 → [`../README.md`](../README.md)「设计原则」；这一步在整条链上的位置 → [`执行层全流程.md`](执行层全流程.md)。
> **谁什么时候读**：建任务工单前——每个进批的桶 1 条。

## 开工前

- 任务工单 = 1 个人群桶（`audiences[]` 1:1），**逐桶建**：任务名/主题按桶派生，任务组/渠道/AB 资源/资源样式/流量策略/计费价格/投放日期/分发方式/曝光上限各桶共用。
- **工单前依赖**：任务组、资源、客群与用户名单都要齐；资源与圈选/名单之间没有先后依赖。名单没建好，`分发方式 = 分发名单 → 用户名单` 就选不到。
- **执行前门控**：负责人标识 / 子业务线 / 是否新建任务组+名字 / **投放日期 + 时间段**，缺一项不启动（见 [`../AGENTS.md`](../AGENTS.md)）。
- **登录身份**：创建前必须拿到非空用户名和 `MPToken/MPUser`；只有旧 Session、没有当前用户名时直接中止。

## 怎么跑

```powershell
# 默认 dry-run：只填 + 校验 + 截图，点「取消」，不创建
.venv\Scripts\python.exe -u automation/scripts/run_taskorder.py --config activities/{活动名}/配置/{品牌}{负责人}.yaml

# 建批：一律直接 --submit
... --submit

# 只建指定桶（先建一个看效果再批量）
... --only A --submit                              # 也支持 --only A,C

# 断点账本不要了，从头全跑
... --reset-progress

# 建完后把新桶批次同步到 v2（task_id 可由下一次取数补全）
... --v2-db 别的.db             # 只在测试/排障时覆盖默认数据库

# 单资源长期单（YAML 里 taskOrder.abTest: false）：同一个命令，脚本自己走「AB测试 = 否」
... --config "<当前执行 YAML>" --submit

--headed                                           # 想看窗口
```

- **建批一律直接 `--submit`**：它本身就是「填完 → 逐字段回读 → 全过才点确定」，正式跑不截图，彩排只是把同一件事做第二遍。彩排只剩一个用途——脚本刚改完、或只想验"配置填得对不对"而**不想动后台**时的干跑。
- **有任一字段没通过 → 关弹窗、不提交，并自动整桶重试一次**：清场 → 重开任务列表 → 从空表单重新填写。第二次仍失败才记 `warn`。已经点过「提交」的失败绝不重试，避免重复建单。
- **中断对账和提交后回读**：统一按 [`脚本通用约定.md`](脚本通用约定.md) 执行；本脚本的核对身份是完整任务名。
- **申请人回读**：回读工单后再查 `createBy`，必须等于当前登录用户名；不一致记 `warn`，但已提交的工单不回滚、不重试，避免重复创建。
- ⚠ **提交成功 ≠ 开始投放**：提交后状态是「**未审核**」，**平台会审，不需要我们（也不需要用户）操作**；审核通过才生成任务、才开始有曝光。在那之前取数接口里查不到这条工单，**别拿它当"建没建成"的依据**。
- 截图落 `activities/{活动名}/日志/taskorder_shots/taskorder_{id}.png`（每桶 1 张，**仅 dry-run 产生**）。

## 断点账本按批次隔离

账本 `activities/{活动名}/日志/taskorder_progress.json` 的键 = **本批完整工单名**，批次后缀天然参与键。
同一活动下一批不会再被上一批的 `submitted` 整桶跳过，**不需要手工归档或 `--reset-progress`**；旧格式
`{任务组}|{桶id}` 不再读取。`--reset-progress` 只在明确要重跑全部条目时使用。

## 投放日期 + 时间段：传参优先，点击兜底

- 默认走**注入表单数据**：在页面 Vue 组件树里找到持有 `dateLimits` / `hourLimits` 的表单组件，`$set` 这两个字段 → 界面自动渲染。格式来自后台 `tTaskInfo/detailPage`（可用列表「查看」录到）：
  `dateLimits = [{timespan: ["开始日", "结束日"]}]`、`hourLimits = [{putDate: "2026-09-14", times: [8..23]}, …每天一条]`（`times` 是**数字**数组）。
- **提交前自检**：回读日期输入框 + 数 `td.active` 格数，对不上就抛错——**绝不带着错日期提交**。
- **兜底**：注入抛错时先把 `dateLimits` / `hourLimits` 清空（防注入一半的状态把回退点击点反），再走 `set_delivery_date_by_click()` 逐格点击。入口 `set_delivery_date()` 负责切换，日志打 `[传参]` 或 `回退点击方式`。
- ⛔ **不要点「新增」**（会多出一个日期段）。逐格点击是只按「日号」点的，跨月区间会点错——这也是默认走传参的原因。

## 已知坑

- **提交按钮叫「提交」，不是「创建」**：名字写错会出现「16 项字段全 ok、界面也不报错，实际什么都没建还返回成功」。找不到按钮一律记 `warn`，不许当成功。
- **下拉必须按「真名 + 分隔符」命中，不能按前缀**：首屏拿到的是**还没被关键词过滤的全量选项**，纯前缀匹配会把同前缀的另一项抢走（选 `…A类 · AI 编程 / Agent 工具` 时命中了排在前面的 `…-4`），工单静默挂错名单、日志里看不出来。`csdn_ui._pick_option` 只认「完全相等」或「真名 + 分隔符」，等不到就抛错——**宁可报错也不选错**。
- **业务线 / 子业务线 / 任务组都是 el-select，选项异步加载**：必须等选项出现再点（找不到会把"看到的选项"列进报错）。
- **任务组 / 用户名单选项极多**（任务组 337 项）：先搜再选（`csdn_ui.search_select`）。
- **AB 资源 / 用户名单的搜索框是 `readonly`**：点外层容器打开 → `page.keyboard.insert_text` 输入（CJK 也能输）→ 点下拉项。
- **多选下拉（分发名单）选完不会自动收**：用 `csdn_ui.close_dropdown()` 点弹窗正文左上角空白收起。别点标题栏（被浮层盖住会超时），也别按 Tab（会把下拉又打开）。
- **单资源长期单（`abTest: false`）是另一套控件**：`资源信息` 块里**不是**三张 `.abtest-resource-item` 卡片，而是 `.resource-row` 里的一个必填下拉（`请输入资源名称搜索`），**且没有流量占比**。这个模式下别找卡片、别填权重。
- **权重 / AB 位次 / 名字角色段三条硬规则**（2 资源桶 50/50、位次不能跳、名字角色段要对上槽位）见 [`../campaigns/README.md`](../campaigns/README.md) §「AB 组三条硬规则」；生成后先跑 [`check_batch_plan.py`](check_batch_plan.md) 挡掉。
- `goto` 用 `domcontentloaded`（`networkidle` 会被 SPA 长连接卡住）；运行加 `python -u` 看实时输出。
- **页面失活**：新页先做页面级探针；`Page.goto` 或探针超时会在尚未提交的前提下重启公共浏览器并重试一次。运行日志落 `activities/{活动}/日志/runs/`。
