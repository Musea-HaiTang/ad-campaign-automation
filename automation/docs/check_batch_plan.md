# 批次 YAML 计划自检 `check_batch_plan.py`（离线，跑后台之前）

> **一句话**：**只读 YAML**，把执行层会被后台拒掉的配置错提前挡掉——不开浏览器、不连后台、秒级返回。
> 和 `check_campaign.py` 的分工：那个是**建完之后**去后台核对对象在不在（要开浏览器、~26 s）；
> 这个是**建之前**核对配置本身（离线）。

## 怎么跑

```powershell
.venv\Scripts\python.exe -u automation/scripts/check_batch_plan.py --config activities/火山引擎MediaKit/调整/2026-10-08-九批.yaml
```

退出码：**0 = 全过；1 = 有错**。有错时**一次列全**（不早退），输出长这样：

```
  D 桶：2 条资源 ｜ 槽位 对照组/实验组2 ｜ 占比 34/33

✗ 自检不通过（4 条）：
  - D 桶：AB 行位次必须是 对照组/实验组1（不能跳行），现在是 对照组/实验组2
  - D 桶：2 条资源的流量占比必须是 50/50（合计 100），现在是 34/33（合计 67）
  - D 桶：AB 行「实验组2」绑的是 `…D类 · 实验1-9`（角色 `实验1`）——名字角色段要和槽位一致
  - D 桶：资源 `…D类 · 实验1-9` 的 role=experiment1 与槽位「实验2」不符
```

## 它查什么（为什么是这几条）

前三条都是 **2026-10-08 火山九批 / KIRO 四批真踩到**的（都在 2 资源桶上，返工 ~3 分钟）：

| 查什么 | 不查会怎样 |
|---|---|
| **权重按资源数算**：3 条 = 34/33/33、**2 条 = 50/50**（合计 100） | 后台拒：`资源流量占比累计为67%，请将流量占比总量调整为100%` |
| **AB 行位次不能跳**：只能 对照组 → 实验组1 →（实验组2） | 2 资源桶把第二条放进"实验组2"会报 `实验组1资源ID不能为空` |
| **资源名角色段 ↔ 槽位一致**（`对照`/`实验1`/`实验2`） | 复盘靠名字认谱系，名字与槽位错位会拿错对象比 |
| **新建资源必须被 AB 引用**；`role` 字段与槽位一致 | 建完没人用的孤儿资源 |
| **名字走 naming**：`taskName` = 桶名、新建资源名 = `桶名 · 角色 + nameSuffix` | 后台按规则名找，手写名字搜不到 |
| **工单字段**：`price`（用户当轮给的正整数）、`deliveryDate.start/end` + 时段、`taskGroup` | `campaign.load` 或后台表单报错 |

**不管**：关键词内容、文案好不好、分发名单在不在后台（那些归 `check_campaign` / 文案自审 / 人工）。

## 什么时候跑

**生成/改完批次 YAML 之后、跑 `run_ads.py` / `run_taskorder.py` 之前**——一次几秒，省的是后台返工。
