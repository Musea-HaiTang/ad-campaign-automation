# 批次计划自检 · `check_batch_plan.py`（离线，跑后台之前）

> **管什么**：**只读 YAML**，把执行层会被后台拒掉的配置错提前挡掉——不开浏览器、不连后台、秒级返回。
> **不管什么**：建完之后后台对象在不在 → [`check_campaign.md`](check_campaign.md)（要开浏览器）；关键词内容 / 文案好坏 → 文案自审 / 人工。
> **谁什么时候读**：批次 YAML 生成 / 改完、跑 `run_ads.py` / `run_taskorder.py` 之前——一次几秒，省的是后台返工。

## 怎么跑

```powershell
.venv\Scripts\python.exe -u automation/scripts/check_batch_plan.py --config "<当前执行 YAML>"
```

退出码：**0 = 全过；1 = 有错**。有错时**一次列全**（不早退）：

```
  D 桶：2 条资源 ｜ 槽位 对照组/实验组2 ｜ 占比 34/33

✗ 自检不通过（4 条）：
  - D 桶：AB 行位次必须是 对照组/实验组1（不能跳行），现在是 对照组/实验组2
  - D 桶：2 条资源的流量占比必须是 50/50（合计 100），现在是 34/33（合计 67）
  - D 桶：AB 行「实验组2」绑的是 `…D类 · 实验1-9`（角色 `实验1`）——名字角色段要和槽位一致
  - D 桶：资源 `…D类 · 实验1-9` 的 role=experiment1 与槽位「实验2」不符
```

## 它查什么

就是把 [`../campaigns/README.md`](../campaigns/README.md)「AB 组三条硬规则」+ naming + 工单字段一起过一遍：

| 查什么 | 不查会怎样 |
|---|---|
| **权重按资源数算**：3 条 = 34/33/33、**2 条 = 50/50**（合计 100）；1 条走单资源模式、无权重 | 后台拒错误权重或错误的 AB 模式 |
| **AB 行位次不能跳**：只能 对照组 → 实验组1 →（实验组2）；1 条资源必须关闭 AB | 2 资源桶把第二条放进"实验组2"会报 `实验组1资源ID不能为空` |
| **资源名角色段 ↔ 槽位一致**（`对照` / `实验1` / `实验2`） | 复盘靠名字认谱系，名字与槽位错位会拿错对象比 |
| **新建资源必须被 AB 引用**；`role` 与槽位一致 | 建完没人用的孤儿资源 |
| **名字走 naming**：`taskName` = 桶名、新建资源名 = `桶名 · 角色 + nameSuffix` | 后台按规则名找，手写名字搜不到 |
| **工单字段**：`price`（用户当轮给的正整数）、`deliveryDate.start/end` + 时段、`taskGroup` | `campaign.load` 或后台表单报错 |

## `nameSuffix`：只在重投时必填

**判据看文件在哪**：当前执行 YAML 放在 `批次/` 时按重投处理，必须带 `nameSuffix`；放在 `配置/` 时按首投整活动 YAML 处理，不校验后缀。历史批次不落文件。

> ⚠ **名字有两个出处**：`活动定义.yaml` 里手写的 `abGroups[].resource` 与 `resources`（由 naming 算）——改命名规则后，记得同步改 `活动定义.yaml` 里那几个 `abGroups[].resource`，否则会出现「新建资源没被任何 AB 行引用」。
