# 圈选用户 · `run_audience.py`（执行层第 3 步 · A 路径）

> **管什么**：怎么跑、后台填什么、建完怎么按日均曝光验收。
> **不管什么**：关键词怎么写 → 流程文档 §5；字段契约 → [`../campaigns/README.md`](../campaigns/README.md)；另一条路（数据平台导 CSV）→ [`run_selection.md`](run_selection.md)；排队 / 断点 / 止损 → [`../README.md`](../README.md)「设计原则」。
> **谁什么时候读**：圈选之前——每桶 1 个客群。

## 开工前

- 后台实体 = **客群**，每桶 1 个。上游是任务组，下游是「一键创建分发名单」（[`run_distribution.md`](run_distribution.md)）——**分发名单不在本脚本内**。
- **A 路径不是当前主要路径**。开工前仍先问用户走 A 还是 B；用户没有指定 A 时，优先按 B 路径执行。
- ⚠ **一律安排在下午跑**：后台数据集每天上午还在写入、一般中午才写完，早上圈出来的数偏小（同款 58 词实测：10:2x = 7,816 → 11:0x = 67,207）。早上跑圈选 = 白跑。（B 路径 `run_selection.py` 没有这条约束——随时可导。）

## 怎么跑

```powershell
# 默认 dry-run：只填 + 读总数 + 校验，不点「确定」
.venv\Scripts\python.exe -u automation/scripts/run_audience.py --config activities/{活动名}/配置/{品牌}{负责人}.yaml

... --submit                                 # 真建
... --submit --verify                        # 真建 + 就地体检（浏览器不关，每 10 秒点一次「查询」，读到数就判达标）
... --submit --name-suffix=-试圈              # 试圈一版（不动正式客群名、不占正式账本）
... --delete "圈选任务名"                     # 删掉（每行先「停止」→ 勾选 → 批量删除）
... --reset-progress                          # 断点账本不想要了

--verify-interval 5 --verify-timeout 1800     # 轮询间隔 / 上限（默认 10 秒 / 900 秒）
```

- 截图 `aud_X_filled.png` **仅 dry-run 产生**。
- **提交前闸门**：圈选任务名 / 子业务线任一回读不过 → 关弹窗、不提交，记 `warn`。
- **正常新建、中断对账和提交后回读**：统一按 [`脚本通用约定.md`](脚本通用约定.md) 执行；本脚本的核对身份是完整圈选任务名。
- **`--verify` 只在 `--submit` 时有意义**（彩排跳过），且只对**这一趟真建成的桶**轮询。出数实测 1~5 分钟（快的 80 秒，慢的 4~5 分钟），赶时间可把 `--verify-timeout` 调小，之后用 `check_campaign.py --only audience` 再补看。读数 / 判定 / 轮询实现在 [`../scripts/audience_metrics.py`](../scripts/audience_metrics.py)。
- 点击、曝光阈值取桶上的 `clickThreshold` / `exposureThreshold`，未配置时使用命令默认 `0/1`。

## 预估圈选总数只记录

`预估圈选总数`只用来观察关键词匹配到多少篇博文，写入日志供排查。它不参与以下判断：

- 不设博文数下限，不因数量少而阻止创建；
- 不设博文数上限，不因数量多而自动调整点击阈值；
- 不把博文数换算成曝光，也不拿它当达标依据。

创建是否成功只看后台任务是否落库；圈选是否达标只看创建后的日均曝光预估。

## 达标口径：建完才看得到

`预估圈选总数` **不是曝光**，别拿它当达标依据。真正的口径是后台「博文圈选任务」列表那几列：

```
创建时间 | 实际圈选博客ID数 | 日均点击(预估) | 日均曝光(预估) | 日均pv(预估) | 关键词列表 | …
```

- **创建弹窗里没有这几项**，要**建完、等后台「圈选用户中…」跑完**才刷出来 → 判断天然在创建之后。
- 达标线：**日均曝光(预估) ≥ 10000**，超过 10000 更好。博文 ID 数只展示，不参与达标判断。
- 一条命令读：`check_campaign.py --only audience`（见 [`check_campaign.md`](check_campaign.md)）。不达标 → **改词重投**（客群重名建不了，重投带后缀）。
- ⚠ **数字受"什么时候量"影响很大**——只认下午量到的数（见开头）。

## 已知坑

- 分析后读总数读的是**显示文本**；没出现说明分析未完成，先条件等待。
- **试圈的断点账本单独一个文件**（`日志/audience_progress.试圈.json`），不污染正式账本——不带后缀时正式账本记着 `submitted`，试圈一个都不会建、还空等轮询。
- `goto` 用 `domcontentloaded`（`networkidle` 会因 SPA 长连接卡住）；运行加 `python -u` 看实时输出。

## 存档：后台另有一套「圈人」口径，本流程不走

后台「圈选用户」还有三条通路。**我们的关键词一律按「关键词博客ID圈选」**（匹配博文内容，见流程文档 §5.1）**来写**，写词不参考下表；哪天要改成圈人再说。

| 通路 | 匹配 | 粒度 | 圈到的人 |
|---|---|---|---|
| ① 搜索词 | 精确 | 具体词 | 站内搜过该关键词的用户 |
| ② Landing 词 | 模糊 | 概括 / 中等词 | 站外点入 CSDN 页面被匹配上的用户 |
| ③ 相似任务 | 关键词重合 | 关键词级 | 与当前关键词重合的历史任务点过广告的用户 |
