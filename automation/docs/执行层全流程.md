# 执行层全流程（把整活动 YAML 变成后台对象）

> **管什么**：执行层**每一步做什么、用哪个脚本、读哪份文档、在哪停下**。
> **不管什么**：YAML 字段规范在 [`../campaigns/README.md`](../campaigns/README.md)；脚本内部实现与踩过的坑在各
> `run_*.md`；投放后的取数 / 判定 / 复盘在流程文档 §9。
> **谁什么时候读**：拿到用户确认的整活动 YAML 之后，**每一次建批**（新活动首投或复盘重投）都从这一页开始。
>
> 上游：流程文档 §8（生成整活动 YAML + 执行层前置门控）。执行层总览与设计原则见 [`../README.md`](../README.md)。

## 0. 一句话 + 一贯的安全口径

一份**整活动 YAML**（`activities/{活动名}/配置/{品牌}{负责人}.yaml`）→ 用 `--config` 指过去 → 按依赖顺序跑脚本
→ 后台依次出现 **任务组 / 资源 / 客群（或分发名单）/ 任务工单**。

- **默认彩排**：不带 `--submit` 就是 dry-run——只填、只回读、只截图，**不点提交**；**加 `--submit` 才真建**。
- **提交前门控**：任一步没通过就**不提交**（关弹窗、记 `warn`、下次重跑）。
- **提交后回读**：点了提交 ≠ 成功，一律回后台列表按名字核对落库。
- 这三条是每个 `run_*.py` 共用的（实现见 [`../README.md`](../README.md) 的「设计原则」）。

## 1. 依赖顺序（不能跳步）

```
① 任务组 run_taskgroup.py
      ↓
② 资源   run_ads.py
      ↓
③ 圈选   ── A 路径：run_audience.py ──┐
          └─ B 路径：run_selection.py ┤（只出 CSV，不建后台对象）
      ↓                              │
③.5 分发名单 ─ A：run_distribution.py（一键创建）
              └ B：run_distribution_ids.py（拿 CSV 建普通名单）
      ↓
④ 任务工单 run_taskorder.py
      ↓
体检 check_campaign.py（只读核对）
```

> **任务的 4 步** = 任务组 / 资源 / 圈选 / 工单；**建分发名单（③.5）夹在圈选和工单之间**，两条路径各有自己的脚本。

## 2. 两条圈选路径 —— 开工前先定走哪条

> 用户 2026-09-21 定：**用哪条先问用户，AI 不自行选**。区别不在"圈得准不准"，在于**圈选结果落在哪、工单挂什么**。

| | **A 路径 · 后台圈选用户** | **B 路径 · 数据平台圈选博文** |
|---|---|---|
| 在哪圈 | 广告后台「3.圈选用户」→「关键词博客ID圈选任务」 | `data.csdn.net`（BI 数据平台）→ 导出 CSV |
| 圈选脚本 | [`run_audience.py`](run_audience.md) | [`run_selection.py`](run_selection.md)（**只导 CSV，不建任何后台对象**） |
| 建名单脚本 | [`run_distribution.py`](run_distribution.md)（在圈选列表点「一键创建分发名单」） | [`run_distribution_ids.py`](run_distribution_ids.md)（拿 CSV 的 `article_id` 建**普通名单**） |
| 两脚本之间 | 可以连着跑 | **必须停下人工看数量**，满意才建名单（数量不满意就不该往下走） |
| 圈选时点 | **固定下午**——后台数据集每天上午还在写入、一般中午才写完，早圈出来的数偏小 | **随时可导**（不受这条约束，用户 2026-09-29 定） |
| 工单挂什么 | **客群** | **分发名单**（工单不再挂客群） |
| 后台有"一键创建"吗 | 有（列表里就有） | **没有**——只有 CSV，所以只能拿 id 手工建普通名单 |

> ⚠ **两条路径不能混着用**：B 路径圈完，后台的圈选列表里没有可点的「一键创建分发名单」，必须走 `run_distribution_ids.py`。
>
> 附带说明：后台「圈选用户」还有一套**搜索词 / Landing 词 / 相似任务**的通路口径——**本流程不走**，
> 存档在 [`run_audience.md`](run_audience.md) 末尾。

## 3. 每一步做什么（逐步表）

> **`--config` 统一指整活动 YAML**；`--only <桶>` 只跑指定桶；`--headed` 显示浏览器；`--reset-progress` 清断点账本。
> 详细开关见各脚本自己的说明书。

| # | 这一步做什么 | 脚本 | 详细文档 | 产出 / 落在哪 | 停下确认 |
|---|---|---|---|---|---|
| 0 | **执行前门控**（AI 自己判，不是脚本） | — | [`../AGENTS.md`](../AGENTS.md)、流程文档 §8 | 三样必给：负责人标识→`taskGroupName` / 子业务线 / 是否新建任务组+名；缺了**不启动** | 是 |
| 0′ | **批次计划离线自检** | [`check_batch_plan.py`](check_batch_plan.md) | 同左 | 秒级、离线：权重按资源数 / AB 位次不能跳 / 名字↔槽位 | 不过就别往下跑 |
| 0″ | 等登录态（只在过期时用） | [`wait_login.py`](wait_login.md) | 同左 | `--site admin`（广告后台，默认）/ `--site databi`（数据平台） | — |
| 1 | 建**任务组** | [`run_taskgroup.py`](run_taskgroup.md) | 同左 | 后台任务组（新建时名 = `taskGroupName`） | 首投才有这一步 |
| 2 | 建**资源**（每桶 2~3 条文案） | [`run_ads.py`](run_ads.md) | 同左 | 后台资源；名字 `{前缀}-{X}类 · {角色}-{N}` | 是 |
| 3A | **圈选用户**（A 路径） | [`run_audience.py`](run_audience.md) | 同左 | 后台**客群**；下午跑；`--tune` 可先看落点 | 是 |
| 3B | **圈选博文**（B 路径） | [`run_selection.py`](run_selection.md) | 同左 | **只有 CSV**，落在 `activities/{活动}/数据/圈选/`；台账 `圈选记录.md` | 看数量 |
| 3.5A | 建**分发名单**（A 路径） | [`run_distribution.py`](run_distribution.md) | 同左 | 后台分发名单（圈选列表「一键创建」） | 是 |
| 3.5B | 建**分发名单**（B 路径） | [`run_distribution_ids.py`](run_distribution_ids.md) | 同左 | 后台**普通名单**（类型 博客ID）；日志打印名单ID | 是 |
| 4 | 建**任务工单**（每桶 1 条） | [`run_taskorder.py`](run_taskorder.md) | 同左 | 后台工单；挂本桶资源 + 本桶客群/名单 | 是 |
| 5 | **体检**（只读核对） | [`check_campaign.py`](check_campaign.md) | 同左 | `--only taskgroup,ads,audience,list,order`；5 类对象在不在、名字一字不差 | — |
| 6 | **等平台审核 → 上线 → 下线老工单** | — | 流程文档 §8 | 工单建好即已提交，状态「未审核」→ **平台会审，不需要我们（也不需要用户）操作**（用户 2026-10-12：「审核不归我管，你只要提交任务了，过一会就有人审核」）；**审核通过才开始投放**；新批跑起来后再下线老批（**先上后下，别断流**） | 后台审核，无需人操作 |

### 复盘重投和首投不一样

| | 首投（新活动第一次） | 复盘重投 |
|---|---|---|
| 任务组 | 建（或沿用已有） | **不建**，按名字沿用 |
| 客群 / 分发名单 | 建 | **一般复用**（只有判定写着"换大名单"才重建） |
| 资源 | 建全部（2~3 条/桶） | 只建**这次要动的桶**那几条（同一批只装要动的桶） |
| 工单 | 全部桶 | 只建这次进批的桶 |
| 物料 HTML | **出**（流程文档 §7） | **不出**（2026-10-09 用户定） |
| 批次记录 | `配置/活动定义.yaml` | 手写 `调整/{日期}-{N}批.yaml` |

> **重投前必须先归档 + 清空任务工单断点账本**（键 = 任务组 + 桶 id、不含后缀，旧轮 `submitted` 会把整桶 SKIP）——
> 见 [`run_taskorder.md`](run_taskorder.md)。账本在 `activities/{活动}/日志/`。

## 4. 每步一停（纪律）

- **建批类动作一律分步走**：一步跑完 → 给用户看后台效果 → 确认后才下一步。**不要一口气跑完 6 步**。
- **一次只跑一条命令**（2026-09-23 实测）：连着在一条命令行里开好几个浏览器会话会撞上「上一个刚关、下一个弹窗还没渲染」，
  报 `Locator.click: Timeout`；同一条命令单独重跑就过。
- **命令行脚本和看板服务互斥**（同一个登录 profile 只能被一个进程用）：要用浏览器时 **AI 自己先停看板服务**
  （关窗口 / Ctrl+C），跑完提示用户重开——用户 2026-09-29 授权"需要用的时候直接关，不用问"。
- **耗时**只记在 [`执行层实测耗时.md`](执行层实测耗时.md)，**不写进流程文档和各说明书正文**。
