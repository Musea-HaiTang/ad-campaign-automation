# 建分发名单（A 路径）· `run_distribution.py`（执行层第 3.5 步）

> **管什么**：怎么在后台「一键创建分发名单」、只读核对怎么核、只有它才会踩的坑。
> **不管什么**：B 路径（拿 CSV 建普通名单）→ [`run_distribution_ids.md`](run_distribution_ids.md)；两条路的区别 → [`执行层全流程.md`](执行层全流程.md) §2；列表页机制 → [`../scripts/list_page.py`](../scripts/list_page.py)。
> **谁什么时候读**：圈选任务建好之后、建工单之前——每条圈选任务一个同名名单。

## 开工前

圈选任务建好后，每一条都要在「圈选用户 → 博文圈选任务」列表里点**该行**的 `一键创建分发名单`，生成与圈选任务**同名**的用户名单；第 4 步工单的「分发方式 = 分发名单 → 选用户名单」才选得到。

## 怎么跑

```powershell
# dry-run：点开按钮、打印确认框内容 + 截图，然后取消（默认）
.venv\Scripts\python.exe -u automation/scripts/run_distribution.py --config activities/{活动名}/配置/{品牌}{负责人}.yaml

... --submit            # 真正创建
... --submit --only A   # 只做指定桶（逐桶推进）
... --verify            # 只读核对：打开「分发名单」页签，看各桶名单是否已建
```

账本 `activities/{活动名}/日志/distribution_progress.json`（键 = 任务组|桶）；截图落 `日志/distribution_shots/`。

## 真机流程

1. 侧边菜单「3.圈选用户」→ 页签 **博文圈选任务**；
2. 目标行点 `一键创建分发名单`；
3. 弹 **message-box**（不是 `el-dialog`，按对话框找会漏）：`是否创建用户名单？名单名称:<客群名>,名单博客ID数:<N>,名单类型:博客ID`；
4. 点 `确定`。若该客群还在圈选中，后台回 `圈选用户中.. 请稍候再试` → 脚本等 30 秒重试，最多 4 次。

## 怎么找到"该行"（全走共用层 `list_page`）

列表是 element-ui 固定列：同一个单元格在 DOM 里有**隐藏副本**（0×0），行内按钮的 `innerText` 在克隆节点里为空——按 DOM 层级 / `get_by_text().first` 都会抓到错的副本。现在的顺序：

1. **筛选框**（`请输入圈选任务名称`，同样有隐藏副本，要挑可见的那份）→ 把目标记录筛成唯一一行 → `lp.row_containing(桶名)`；
2. 行内按钮结构定位：行里 `button:visible` 按文案命中；
3. 坐标兜底：结构摸不到时，按这一行的 y 中线找同排按钮。

> **保险丝**：圈选任务行按完整任务名定位；弹窗出现后必须包含完整目标名单名，不匹配就取消并报错。

## 提交后回读

正常新建不预读名单。提交后切到「分发名单」页签，按完整名单名做精确行查询；三态和恢复规则见 [`脚本通用约定.md`](脚本通用约定.md)。

- 为什么必须回读：账本里的 `submitted` 是**永远跳过**，误记就等于这桶再也不建；而"提示为空"不能当成功——实测 A/B/C/E 建成功时 `.el-message` 是空的，D 报的 `圈选用户中` 是别的桶的残留提示。
- 关键词只看"明显失败/要重试"：出现 `圈选用户中… 请稍候` → 等 30 秒重试；出现 `失败/错误/已存在/不能/异常` → 记 `warn`。

## `--verify` 只读核对的规矩

「分发名单」列表是**全系统**的、一页 30 条，两步都要做到位，否则会把已建的报成「未找到」：

1. **按完整名单名筛**——不用活动前缀或桶名前缀，避免旧名单造成假命中；
2. **等筛选结果真正刷新**——点查询后等表格文字签名变化；不变就返回 `UNKNOWN`，不能报“不存在”；
3. **等表出数据要限定当前可见页签**（`.el-tab-pane:visible`）：所有页签都留在 DOM 里、隐藏页签的表也有行。
