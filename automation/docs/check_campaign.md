# 活动体检 · `check_campaign.py`（只读）

> **管什么**：建完之后核对后台 5 类对象在不在、名字一字不差，顺带做客群达标体检。
> **不管什么**：配置本身对不对 → [`check_batch_plan.md`](check_batch_plan.md)（离线、不开浏览器）；取数与看板 → [`fetch_perf.md`](fetch_perf.md) / [`visualize_perf.md`](visualize_perf.md)。
> **谁什么时候读**：交付前、复盘中、怀疑"没建成"时。

资源检查按**桶名前缀**搜索：例如搜 `腾讯云产品-hang-AI创作`，等筛选结果刷新后读取**全部分页**，再按完整资源名全等匹配。版本差异必须已经写进配置名，不能再把 `实验2` 当成 `实验2-5`。查询或翻页失败报 `未确认`，不能报 `缺失`；只有搜索成功且所有页都读完仍找不到，才算确认缺失。额外资源只忽略，不算错误。

2026-10-21 真机曾出现任务组下拉为 0 选项、旧逻辑只读当前页/旧表，把后台实际存在的 `AI创作 · 实验1/实验2` 误报为缺失。后续禁止再按完整资源名逐条搜索，也不能只读第一页。

## 怎么跑

```powershell
# 全查（任务组 / 资源 / 客群 / 分发名单 / 任务工单）
.venv\Scripts\python.exe -u automation/scripts/check_campaign.py --config activities/{活动名}/配置/{品牌}{负责人}.yaml

# 只查某几类：taskgroup,ads,audience,list,order
... check_campaign.py --config <yaml> --only ads,order

# 只做客群达标体检（默认口径：日均曝光预估 ≥ 10000）
... check_campaign.py --config <yaml> --only audience

# 用户当期给了不同阈值时再覆盖
... check_campaign.py --config <yaml> --only audience --min-exposure <阈值>

--headed   # 想看浏览器窗口
```

- **退出码**：全部找到 = 0；有缺失 = 1（可以串进别的流程当门禁）。
- **只读**：只填筛选框 + 点「查询」，**绝不点** 新建/创建/确定——`list_page` 里根本没有写入动作，这是结构上的保证。名字一律问 `naming.py`（后台按精确字符串匹配，差一个字符就是没有）。

## 客群已删、分发名单还在 → 不算缺失

重投 / 换词之后经常把**圈选任务删掉、只留分发名单**——工单认的是**分发名单**，投放不受影响。判定：

| 客群 | 分发名单 | 结论 |
|---|---|---|
| 在 | 在 | `✓` |
| **不在** | **在** | `ⓘ 客群已删、分发名单在，不算缺失`（只在报告里提一句，**不影响退出码**） |
| 不在 | 不在 | `✗ 缺失`（真缺失） |

客群缺失时会**补查一次**「分发名单」页签来核这一条（`--only audience` 也会补查）；提示里带一句"下次改词重圈时按新任务走"。

## 客群达标体检

查客群时顺带读「圈选用户 → **博文圈选任务**」列表的四列，逐桶判达标：

```
实际圈选博客ID数 | 日均点击(预估) | 日均曝光(预估) | 日均pv(预估)
```

| 日均曝光(预估) | 判定 | 动作 |
|---|---|---|
| ≥ 10000 | 达标 | 继续 |
| < 10000 | 不达标 | **改词重投**（客群重名建不了，重投带后缀） |
| 读不到（`—`） | 待后台 | 后台还在「圈选用户中…」，等算完再跑一次 |

- ⚠ 这几项**建完、等后台算完才刷出来**——创建弹窗里没有，所以体检只能在创建之后做。
- ⚠ **`预估圈选总数` 不是曝光**：它数的是博文ID个数，不区分有没有流量。
- 达标只**报数**，**不影响退出码**（退出码仍只表示"对象在不在"）。

## 每类怎么查

| 类别 | 列表页 | 用什么筛 |
|---|---|---|
| 任务组 | `#/distribute/taskteam/team` | 输入框 `请输入任务组名称` ← `campaign.taskGroupName` |
| 资源 | `#/distribute/resource/list?channelType=page` | 按桶名前缀搜索 → 读全部分页 → 完整资源名全等核对 |
| 客群 | `#/distribute/distUser`（侧边菜单「圈选用户」→ 页签 `博文圈选任务`） | 输入框 `请输入圈选任务名称` ← 活动前缀 |
| 分发名单 | 同上 → 页签 `分发名单` | 输入框 `分发名单模糊查询` ← 活动前缀 |
| 任务工单 | `#/distribute/distApplyOrder/list` | 输入框 `请输入任务名称模糊查询` ← 活动前缀 |

## 坑（都已在脚本里兜住）

1. **资源列表按桶名前缀搜索**：一次读当前桶全部分页，再在本地按完整资源名全等比较；不依赖会异步返回 0 选项的任务组下拉。
2. **输入框有隐藏副本**（element-ui 固定列 / 克隆）：必须挑**可见且宽度 > 0** 的那一份。
3. **进「圈选用户」要先点侧边菜单**再点页签，直接 `goto` 页签不生效。
4. **一条记录被拆成三份 DOM 行**（冻列）：主表放「日期 + 四个数 + 关键词」、左冻列放「ID + 名称」、右冻列放按钮——按**行号**合并成一行再解析，单看任何一份都认不出。
5. ⚠ **客群列表默认只筛最近 4 天**——老客群被挡在列表外会误报「客群缺失」。脚本已自动把开始日期拉到 `2020-01-01`（日志打 `[日期窗] 2020-01-01 ~ 今天 ✓`）。
6. ⚠ **资源列表也有默认创建时间窄窗**，老资源会被挡在列表外、误报「资源缺失」。脚本已自动填 `2020-01-01 ~ 今天`；日期窗没填上时只允许报「未确认」。

## 名字从哪来

- **客群名 / 分发名单名**：优先取 `audiences[].distributionList`（`run_taskorder.py` 选名单就是按它选的），**没写才回落** `naming.order_task_name()`（`{桶名} · {topic}` + `nameSuffix`）——重投**复用旧名单**（名字不带 `-2`）时，按命名规则算会去找一个不存在的名字，误报「分发名单缺失」。
- **资源名 / 工单名**：永远按命名规则（`naming.py`，含 `nameSuffix`）——重投建的就是新对象，复用旧名单 ≠ 复用旧工单。
