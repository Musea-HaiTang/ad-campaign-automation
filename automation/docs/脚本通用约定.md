# 脚本通用约定

> **管什么**：所有执行脚本共同遵守的命令、安全边界、浏览器、恢复、日志和结果口径。
> **不管什么**：各脚本独有的字段、后台操作链和坑 → 对应 `run_*.md` / `check_*.md`；整条执行顺序 → [`执行层全流程.md`](执行层全流程.md)。
> **谁什么时候读**：第一次跑脚本，或新增、修改脚本之前。

## 命令

- 在仓库根目录执行。
- 固定使用 `.venv\Scripts\python.exe -u`，不依赖系统 `python`。
- 新建类脚本默认 dry-run；只有显式 `--submit` 才往后台写入。
- `--headed` 显示公共浏览器，`--only` 限定桶，`--reset-progress` 只在确认要重跑全部条目时使用。
- `--v2-db` 只用于测试或排障，正常运行使用 `activities/_db/投放数据.db`。

建批链按步骤串行执行，每步结束先确认结果。只读命令可以另开标签页运行；只有 `run_selection.py --parallel` 这类明确支持并发的脚本例外。不要把两个 `--submit` 同时启动，全局写锁会直接拦下第二个。

## 提交前后

1. 填写完成后先做逐字段回读；任一步未通过，关闭弹窗，不提交。
2. 正式写入前先把条目记为 `submitting`，同时保存 payload 指纹。
3. 点击提交后只认服务端回执和列表页精确回读，不把“弹窗关闭”或“操作成功提示”当最终成功。
4. 已点过提交的动作不盲目重试；无法确认时记 `needs_reconcile`，下次先查远端。

## 中断恢复

- 正常新建不预读后台。
- 只有上次状态为 `submitting`、`needs_reconcile`、`warn` 或 `fail` 的条目，下一次才做定点对账。
- `FOUND`：远端已存在，复用并记 `submitted`。
- `ABSENT`：确认不存在，重新执行。
- `UNKNOWN`：查询失败或页面未刷新，记 `needs_reconcile` 并停止该项。
- 同一业务键再次出现但 payload 指纹不同，记冲突并停止，不覆盖远端对象。

账本状态由 `automation/scripts/bucket_runner.py` 统一定义：

| 状态 | 含义 |
|---|---|
| `done` | dry-run 已校验，只供彩排跳过 |
| `submitted` | 远端已确认存在，永远跳过 |
| `submitting` | 已进入写入流程，结果尚未安全落账 |
| `warn` | 有校验失败或结果不确定 |
| `needs_reconcile` | 必须先查远端，禁止直接重做 |
| `fail` | 本次执行失败 |

## 公共浏览器与登录

- 只有 `browser_broker.py` 持有登录浏览器；首选 CDP 端口 `9222`，冲突时读取状态文件中的实际端口，不假设固定值。
- 每个脚本只操作自己的标签页；不要关闭公共 context 或浏览器。
- 页面级探针失败时先重启 broker，再重新打开目标页。
- 登录身份不完整时先跑 [`wait_login.md`](wait_login.md)，不要靠“页面能打开”判断登录有效。

## 结果与日志

- 每项和整趟都打印耗时；结尾打印 `RESULT: OK / HAS_WARN / HAS_FAILURES`。
- 只有 `OK` 返回退出码 0；警告、失败或未确认都返回 1。
- 运行日志自动落到 `activities/{活动}/日志/runs/`；没有活动目录时落到 `automation/_tmp/runs/`。
- 排障先看日志中的失败步骤、远端三态、页面恢复和 `RESULT`，不要仅凭进程退出判断业务成功。

## 名称与查询

- 桶、客群、分发名单、资源、工单和物料文件名由 `automation/scripts/naming.py` 生成。
- 后台核对按完整名称精确匹配；禁止用整页包含、公共前缀或任务名尾号判断成功。
- 筛选后先等当前可见表格真正刷新，再读行；查询失败返回 `UNKNOWN`，不能伪装成“不存在”。

脚本自己的说明书只保留该脚本的独有参数、后台操作链和特殊坑；通用规则不再逐篇复述。
