# 文案自审循环（写文案的最后一道关）

> 状态：**必过流程**——每条文案定稿前都要走一遍（用户 2026-09-24 明确：「这个你记下来，以后每次你都这样做」）。
> **谁审**（用户 2026-09-28 定）：**自审由 AI 自己负责**——判据也由 AI 自己维护，不要求用户给标准。
> 用户现阶段**只看最后的过程展示**；**目标是全程自动化，最终连这一步也不需要人看**。
> 位置：`../流程文档/CSDN广告投放自动化流程.md` §6.3 引用本文；两种类型的写法见 [`两种文案类型.md`](两种文案类型.md)。

## 什么时候走

写文案（§6）→ **本循环** → 出物料。**没过完这一关的文案不出物料、不进 YAML。**

## 判据清单（AI 自用 · 一条不过就回炉 · 2026-10-12 重构）

> **判据由 AI 自己维护**（2026-09-28）：下面是 AI 现在用的版本，可以按数据结果自己迭代；
> 它们不是用户定的标准，也不需要用户先批准。
> **2026-10-12 用户点出「我们的自审环节有点粗糙了」** → 当日重构：原来问的都是"会不会踩坑"，
> 现在**每条定稿必须落笔写出三样东西**——`停点词 = ___ ｜ 差异类型 = ___ ｜ 出处 = ___`，
> **写不出来 = 那一关没过**（这是防"自审走过场"的硬约束）。
> 新增 **第 2 关「凭什么是你」**（竞品替换测试 + 差异四类，用户点名要的）和 **第 5 关「他凭什么信」**；
> 顺序：**先过第 0 关（通顺）** → 1~5 关 → 最后硬扫。

1. **目标人群视角：他会停下来看吗？**（**2026-09-30 用户指出缺了这条**，现在放第一关）
   ⛔ 后面三关问的都是"写得好不好"，这一关问的是**他会不会停**——扫读位上是
   **曝光 → 停下来看 → 点击**，**停不下来 = 后面写得多对都没用**。
   做法：把自己**换成这个桶的具体人群**（不是泛泛的"读者"，是这个人群此刻在干的活），三问——
   - 我写的是**他要的东西**，还是**我们想说的东西**？（"同一套接口"是我们的卖点，"转码和字幕不用跑两遍"是他的活）
   - 标题里有没有**他自己的话 / 他手上的脏活**？（说不出他上周干过的那件事 = 没有）
   - **他扫到哪个词会停下来？**——指得出来才算过（指不出来就是没有；指得出来就把那个词放标题前段、或拿它飘红）
   - **这个卖点是"行业标配"吗？**（**2026-10-12 用户点出**：缓存命中便宜是行业标配，读者觉得"本来就该这样"，**不会有反应**）——
     标配功能不算钩子；要指得出一件**他正在付代价的事**（迁移要重写、要开好几家账号、要自己写对接），或者这家**独有**的东西。
2. **凭什么是你（差异化）**（**2026-10-12 用户点名**：看看这个卖点相对竞品有没有优势）：
   光"对他有用"不够，还得说清"**为什么不是别家**"。
   - **竞品替换测试（必做）**：把主语的品牌换成同类的另一家（阿里云百炼 / 火山方舟 / 自建开源 / 通用低代码平台），
     **这句话还成立吗？**——成立就说明它是**行业标配**（缓存便宜、有免费额度、有价目表、能接 IM、有 RAG…），
     读者的第一反应是"本来就该这样"，**不能当钩子**（用户原话：缓存命中便宜不是应该的吗）。
   - ⚠ 这是**自审时的内部测试**，不是让你在文案里写竞品对比——"只正向陈述、不拉踩同行"是红线（§6.2）。
   - **差异必须落到这四类里的一类，并在自审记录里写出是哪一类**：
     - **省步骤**：他的活本来要 A→B→C，这里一步——例："改一个 model 字段"（步骤数能数出来）
     - **省成本**：官方明写的**量级差**，不是"更便宜"这种形容词——例："套餐比按量省超一半"
     - **别人做不到**：合规 / 私有化 / 数据不出域 / 白名单这类**约束性差异**
     - **独有资源**：自研模型、独家合作、官方背书、生态入口——例：混元自研、企微与钉钉生态、信通院评估
   - **兜底**：四类都落不进去 → 这条**不该上**，回想法池换下一条未验的；**别在词句上磨**。
3. **看得懂、记得住**：把自己当成刚读完文章、正在底部扫推荐位的目标读者，只给标题 3 秒——
   「这跟我有什么关系？」「我会不会点？」（说不出具体的人 = 没钩子）
   再加两问：**要不要心算 / 切语言？**（数字串、两数并列、一串英文专名 → 换中文说法，最多留一个这批人本来就认识的）；
   **合上眼能复述出"这条讲的是 ___"吗？**——复述出来的那件事，必须正是我们打算让他记住的那件事。
4. **像不像他要读的东西**：
   - ①型（伪装成推荐博文）问：**会不会被当成广告一眼划过？**
   - ②型（纯营销类）问：**有没有一个具体的好处？**
5. **他凭什么信**（**2026-10-12 加**）：
   - **每句话都能指到出处**——活动细则 §2 的事实表 / 官方页面与文档原话 / 后台实测数；
     自己推的机制、替读者下的结论，**一律删掉或换成官方说法**；
   - **没有绝对化**（最 / 第一 / 彻底 / 完美 / 唯一，除非是官方原文且用户认可）；
   - **数字只用核到的**，没核到的宁可不写。
6. **纪律扫描（硬扫）**：空话（「不用那么麻烦」）、能力清单堆砌、读者视角错位（写「重学」「学两套 API」这类读者没说过的事）、
   场景太窄、一串英文专名、**没核到的数字**、拉踩同行、全局红线（忌「翻墙」）。
7. **通顺（第 0 关 · 先过它，2026-10-08 用户点出来的）**：**把标题和摘要出声读一遍**——主谓宾齐全、不乱序、不半截话、
   不用书面腔堆从句。**这是最基础的关**，不通顺的句子前面几条过得再好也没用。
   - 用户点名的反例：`10 月 24 日长沙现场统一 3 小时做完就路演`（缺停顿、主语跳）→ 改成
     `10 月 24 日长沙现场，3 小时做完之后直接路演`（顺带删掉"统一"这个多余的词——用户 2026-10-08：字数能省就省，别用不传递信息的修饰词）。
   - 另一类反例：小改时为了砍字把句子砍成半截——`手上那套 ffmpeg 脚本，换成在对话里说一句`（换成什么？说一句什么？）、
     `抠图边缘老是毛边，换成现成的图像包`（换掉什么？）。
   - ⚠ **"小改"同样要过这一关，也要过活动硬口径**（本活动的硬口径见各活动 `活动细则.md`）——
     去模板 / 砍字的时候最容易把这两样一起丢掉。

## 小改怎么做（2026-10-12 加 · 用户点出「小改很粗糙」）

> 起因：2026-10-12 那轮 4 条小改全是"摘要补截止日 / 去公文词 / 标点顺句 / 改人称"——**标题一个字没动、钩子词一个没换**。
> 用户一眼看出来：「我感觉你的小改很粗糙呀」。**粗糙的不是文笔，是没动钩子。**

**小改三步，一条都不能省：**

1. **先指认钩子**：写下"这条现在的**钩子词 = X**，他会在 X 上停住"。
   ⛔ 指不出来 → 这条**不该小改、该换角度**（表达问题才小改，钩子问题要换）。
2. **必须动钩子层的一处**，三选一（不许一个都不动）：
   - **换钩子词**：同一个角度里更狠、更贴他原话的那个词；
   - **挪位置 / 换飘红**：钩子词必须在**标题前段**或**飘红位**（判据 1 的第三问）；
   - **补他自己的话**：把他心里那句原话放进标题（判据 1 的第二问）。
3. **写清这条小改在验什么**：小改**也要挂存疑**（"把钩子从 A 挪到 B，看点击率涨不涨"）；挂不上就不算一次小改。

**"顺句微调"不是小改**：只改标点、补时间点、去重复词、改人称——**可以顺手做，但不消耗小改预算、也不算验过一轮**。
（2026-10-12 起按此区分，否则"每轮都要有槽位在验新变量"会被顺句微调悄悄吃掉。）

> 验收口径（[流程文档 §9.3](../流程文档/CSDN广告投放自动化流程.md)）：小改后**点击率涨了 → 可以继续小改**；
> **没涨 → 换角度**；**单条资源级 CTR ≥ 千三 → 一个字都别动**（长期单候选）。

## 循环怎么走

初稿 → **先过通顺（第 0 关 = 清单第 7 条）** → 再逐条过 **1~6 条（先过第 1 条）** → 不合格的**只改卡住的那一点**重写 → 再审 → 直到全过。

- **卡在哪一关就只改那一点**，改完**从第 0 关重走**（通顺）。
- **同一个角度改 2 轮还过不去 → 换想法池里的下一条**：表达问题才小改，**钩子问题要换角度**，别在词句上磨。
- **定稿必须留下三字段**（写进自审记录）：`停点词 = ___ ｜ 差异类型 = 省步骤/省成本/别人做不到/独有资源 ｜ 出处 = ___`。

- **2–3 轮是正常的**；一遍就过，通常说明判据没过脑子。
- 回炉时**保留过程**：这一稿卡在哪一关、改了什么、为什么这样改。

## 交付时必须展示过程（用户 2026-09-24 要求，现阶段）

给用户看文案时**不只给结果**，要展示循环：

```
v1「<初稿>」→ 自审：<卡在哪条判据> ✗
v2「<第二稿>」→ 自审：<还剩什么问题> ✗
v3「<定稿>」→ 自审：<为什么过> ✓
定稿三字段：停点词 = ___ ｜ 差异类型 = ___ ｜ 出处 = ___
```

目的：让用户看得见 AI 的判断标准，流程才好改。

> **这是过渡期要求**（2026-09-28 明确）：目标是把文案这一环做成**全程自动化**——
> 到那时用户不必再看过程，AI 自己审、自己定稿、自己按数据换。

## 常见的不合格类型（从真实回炉记录里攒）

| 不合格类型 | 真实例子 | 改法 |
|---|---|---|
| 空话 | 「接音视频 AI 不用那么麻烦」 | 换成读者能对上的具体动作：「不用 OAuth、不用配 STS」 |
| 视角错位 | 「ffmpeg 不用重学」 | 读者没说要学；换他真实的动作「参数不用背」 |
| 能力清单 | 「字幕擦除、语音转字幕，Agent 都能做」 | 给坐标：「做二创，先把原片自带的字幕擦干净」 |
| 场景太窄 | 「想让 Agent 直接看懂录屏」 | 换更大的人群场景（该条实测 4,718 曝光 / 1 击） |
| 堆英文专名 | 基准名、框架名一串 | 换中文说法，最多留一个本批人本来就认识的 |
| 自己造纪律 | AI 自己提炼的"禁忌" | 特例只由用户给，AI 去问 |
| **不通顺 / 半截句**（2026-10-08 用户点出） | 「10 月 24 日长沙现场统一 3 小时做完就路演」（缺停顿）；小改砍字砍成「手上那套 ffmpeg 脚本，换成在对话里说一句」 | 出声读一遍，补上主语和停顿；宁可多两个字也不要半截话 |
| **标配功能当卖点**（2026-10-12 用户点出，原话「缓存命中便宜不是应该的吗，你这个一点吸引力都没有」） | 「反复发同一段提示词，缓存命中单独计价」（TokenHub 实验2 槽位） | 换成"他正在付代价的那件事"或这家独有的能力：改成「生图、生视频、生 3D，一个 Key 调完」（一个账号调多模态，省掉开好几家） |

## 边界

- **自审不能替代数据**：它只保证"不犯低级错误"；哪条真的行，**由点击数据说了算**。
- **AI 自己审、自己定稿，不需要用户介入**（2026-09-24 用户定，2026-09-28 明确为"目标全自动"）：
  写文案阶段 AI 按本文定稿即可；用户只有**特别喜欢 / 特别不认可**某条时才提出来，其余一律交给数据。
