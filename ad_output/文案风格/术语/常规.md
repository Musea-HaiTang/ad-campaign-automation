# 常规

> **管什么**：常规文案的唯一定义、基线与二级手段边界。
> **不管什么**：三种风格 → 本目录各风格术语文件；审核流程 → `../文案自审.md`。
> **谁什么时候读**：写对照基线、判断一个标签是否为风格、或使用二级手段时。

## 定义

常规是不套对仗、化用或借鉴诗词，直接用读者能一眼看懂的话写清角度、动作、结果或数字的文案。

常规是**对照基线**，不是第四种风格。

## 写法

### 1. 从读者的具体时刻起笔

先写读者已经经历过的具体动作、麻烦或损失，不写“提升效率”“优化体验”这类抽象需求。

这个时刻要满足：

- 能还原成一个画面；
- 目标读者会觉得“就是我”；
- 能自然连到产品机制、活动动作或具体收益。

### 2. 标题给出结果与方案

标题优先写清两件事：

- 读者想要的结果；
- 产品或活动怎样帮他做到。

“想让 X，就 Y”可以作为可选句式，但不是统一模板：

- X 写读者想要的结果，不写痛点或已经完成的事实；
- Y 写动作 + 产品形态 / 具体能力 / 参与方式；
- 其他能直接讲清结果和方案的句子同样可用。

标题以“一口气能读懂”为准，不设固定字数模板。

### 3. 摘要先写时刻，再写怎么改变

摘要建议用两句完成：

1. 第一句写读者昨天亲手做过的那件事或遇到的麻烦；
2. 第二句写产品或活动怎样接走同一个动作，并落到机制、结果或参与方式。

第二句要点名产品形态或参与方式，让读者知道是谁、用什么方式改变了这件事。

### 4. 两句之间要有承接

痛点句和机制句不能各说各的。常用三种承接方式：

| 承接方式 | 写法 |
|---|---|
| 时间 / 动作承接 | `装完这个技能包，……`、`提交作品后，……` |
| 问句承接 | 第一句写成读者遇到的问题，第二句直接回答 |
| 主语回指 | `这套能力……`、`这个活动……` 直接接住第一句的动作 |

一条文案选一种承接方式即可，不必强行套满。

### 5. 写作顺序

1. 使用 `../选角度.md` 已确认的角度；
2. 写清这个角度对应的“读者昨天那一刻”；
3. 写产品或活动怎样改变同一个动作；
4. 最后压缩成标题与摘要；
5. 按 `../文案自审.md` 检查。

## 可选起稿骨架

```text
角度：
读者昨天那一刻：
产品 / 活动怎样改变它：
标题：
摘要第一句（具体时刻）：
摘要第二句（谁、通过什么、带来什么结果）：
```

这只是思考顺序，不是固定句式；不要为了套骨架写出不自然的广告话。

## 使用规则

- 常规可进入任意资源位，不设每批数量上限；同一批仍先保证角度不重复；
- 常规标签只用于对照，不参与“三种风格”计数；
- 不编造数字、能力、体验或用户原话；
- 标题和摘要要能连续读通，第二句要回答第一句提出的问题；
- 一行里避免堆多个英文专名；
- 常规文案可以按需使用二级手段：悬念 / 反差、直击问句、场景白描、类比 / 借物、拟人 / 第一人称、对话体；
- 二级手段用于组织表达，不单独成为风格标签。

## 二级手段

以下是写常规文案时可用的辅助手段，不单独成为风格标签，也不与三种风格混写。

| 手段 | 示例 |
|---|---|
| 悬念 / 反差 | `设计稿还没定，前后端代码先出来了` |
| 直击问句 | `几万人的库，搜一次要等多久？` |
| 场景白描 | `下午五点丢给它的活，第二天早上已经在桌上` |
| 类比 / 借物 | `给智能体一间自己的办公室` |
| 拟人 / 第一人称 | `活我干完了，你回来收就行` |
| 对话体 | `同事问我能不能做刷脸，我说控制台点一下就能开通` |

## 与三种风格的边界

- 出现严格对应结构并标为对仗时，归 `对仗.md`；
- 基于诗词、古文、名人名言、歇后语、俗语或谚语改写时，归 `化用.md`；
- 保留真实诗词原句片段时，归 `借鉴诗词.md`；
- 没有明确出处的自写古风句不能标成化用或借鉴诗词，应改写成常规。
