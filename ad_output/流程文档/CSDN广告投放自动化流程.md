# CSDN 广告投放 · 自动化流程

> **管什么**：阶段顺序、跨阶段硬约束、停下点和子流程入口。
> **不管什么**：活动启停 → [`活动启停流程.md`](活动启停流程.md)；选角度 → [`选角度流程.md`](选角度流程.md)；复盘与小改 → [`想法池与1000曝光复盘流程.md`](想法池与1000曝光复盘流程.md)、[`小改流程.md`](小改流程.md)；术语 → [`术语真源.md`](术语真源.md)；执行细节 → [`执行层全流程.md`](../../automation/docs/执行层全流程.md)。
> **谁什么时候读**：任何阶段先读本文件，再按 §1.1 进入当前阶段的文档。只读当前活动、当前阶段需要的资料。

---

## 0. 核心规则

| 规则 | 当前口径 |
|---|---|
| 用户闸门 | 物料 HTML 未经用户确认，不生成 YAML；YAML 未经用户确认，不进入执行层。新增产品还须在词表、角度与想法池处停下。 |
| 活动边界 | 活动名、产品事实、用户特例和数据只写当前活动目录；不翻其他活动当模板。 |
| 活动特例 | 仅由用户提供。发现疑似特例先问用户，AI 不自行提炼纪律。 |
| 创意格式 | 一条文案 = 角度（说什么）× 风格（怎么说）。标题 + 描述两行，无 CTA。 |
| 文案底线 | 文案和物料不得出现「翻墙」；只正向陈述自家卖点；动作词必须符合产品形态。 |
| 圈选路径 | A = 后台圈用户，固定在下午；B = 数据平台圈博文，随时可导。开工先问用户，当前通常走 B。 |
| A 路径达标 | 后台「日均曝光(预估)」≥ 10,000，越多越好。博文数只展示，不参与判断。 |
| 后台对象 | 1 桶 = 1 工单 = 1 客群或 1 名单 × 2～3 资源；3 资源权重 34/33/33，2 资源 50/50。 |
| 投放配置 | 预算在后台统一设置，不按桶差异化。 |
| 当期输入 | YAML 前必须向用户确认所有无法从资料推导的当期字段；清单见 §8。历史值不套用。 |
| 判定 | 工单累计曝光达到该桶门槛后判定；状态、补验和小改按 §9 执行。 |
| 唯一实现 | 后台名称只由 `automation/scripts/naming.py` 生成；运行期数据只以 `activities/_db/投放数据.db` 为准。 |

## 1. 流程总览

| 步骤 | 输入 | 动作 | 产物 | 停下点 |
|---|---|---|---|---|
| 1 | 活动链接 + 要求 | 查产品与活动事实 | 产品事实表 | 查不清就停 |
| 2 | 活动身份 | 建或更新活动细则 | `物料/活动细则.md` | 特例不明就停 |
| 3 | 目标读者 | 拆人群并过钩子闸门 | 最终桶 | — |
| 4 | 每个桶或产品 | 写关键词，定圈选路径 | 每桶一行关键词 | 新增产品停 |
| 5 | 冻结角度 | 建想法池，取 2～3 条未验文案并自审 | 待投文案 | 新增产品停 |
| 6 | 关键词 + 文案 | 生成投放物料 HTML | `物料/投放物料/*.html` | 用户确认 |
| 7 | 已确认物料 + 当期参数 | 生成 YAML，离线自检，执行建批 | 整活动或批次 YAML、后台对象 | 用户确认 YAML |
| 8 | 后台数据 | 取数、判定、复盘、建下一批 | 复盘与下一批动作 | 到期即进入复盘 |

活动启动、建下一批、收尾和恢复的操作清单见 [`活动启停流程.md`](活动启停流程.md)。

### 1.1 分阶段阅读

| 阶段 | 只读这些 |
|---|---|
| 1～2 摸产品、建细则 | 活动链接正文、本活动 `活动细则.md`、[`活动细则模板`](../../activities/_活动细则模板.md)；联网搜索由当前 AI 产品提供 |
| 3～5 分人群、关键词、文案 | `ad_output/AGENTS.md`；本文件 §0、§4～§6；[`选角度流程.md`](选角度流程.md)、[`想法池与1000曝光复盘流程.md`](想法池与1000曝光复盘流程.md)、[`术语真源.md`](术语真源.md)；`文案风格/`；`memory/MEMORY.md` 与对应暂缓经验 |
| 6～7 物料、YAML、执行 | [`投放物料/README.md`](../投放物料/README.md)、[`campaigns/README.md`](../../automation/campaigns/README.md)、[`执行层全流程.md`](../../automation/docs/执行层全流程.md) 及当前步骤的脚本说明 |
| 8 取数、判定、复盘 | [`fetch_perf.md`](../../automation/docs/fetch_perf.md)、[`judge_batch.md`](../../automation/docs/judge_batch.md)、[`visualize_perf.md`](../../automation/docs/visualize_perf.md)、[`web/README.md`](../../web/README.md)、本活动 `数据/`、数据库 `review` / `review_resource` |

数据里的点击率用于验证，不是写文案的素材。YAML 字段、脚本参数和别家活动文案不在当前阶段默认阅读范围内；确需阅读先问用户。

### 1.2 活动类型

摸产品前先判断类型，并写入 `活动细则.md` 第 0 项。

| 维度 | 单页活动 | 多产品活动 |
|---|---|---|
| 桶的来源 | 按人群搜索意图拆桶 | 一个顶格产品 = 一个工单 |
| 每桶内容 | 人群 + 钩子 → 选角度 → 按 `resources` 出 2～3 条文案 | 产品 → 选角度 → 按 `resources` 出 2～3 条文案 |
| 钩子闸门 | 每人群须有 2 个不同钩子 | 不设钩子闸门 |

其余步骤共用。多产品活动的目标是覆盖全部产品，靠数据淘汰，不设上量闸门。

### 1.3 新增产品

| 步骤 | 动作 | 产物 | 停下点 |
|---|---|---|---|
| 1 | 按 §2 查产品，补入活动细则 | 产品事实 | — |
| 2 | 按 §5 写关键词，整理对应数据 | 词表与对应数据；写入 `活动定义.yaml` 的 `buckets[]` | 给用户看词表与对应数据 |
| 3 | 走 B 路径导 CSV、核对数量、建分发名单 | 圈选 CSV、后台名单 | 看数量 |
| 4 | 建读者证据卡、角度句、3 个主角度和验证位 | `物料/待验证想法/{产品}.md` | 给用户看角度与想法池 |
| 5 | 按 `resources` 取 2～3 条未验文案并自审 | `copies` | 自审归 AI |
| 6 | 出物料、生成 YAML、执行建批、体检 | 物料、YAML、后台对象 | 物料和 YAML 均须用户确认 |

- 名单在词表冻结且用户点头后当场建；词表一改，名单作废。
- 新桶写 `reviewThresholdExposure`：按产品工单曝光速度定，首次默认 3,000；之后只在用户明确给新值时调整。
- 执行层只跑新桶：`--only <产品名>`。
- 剩余产品按 `物料/产品清单.md` 的热门排名从上往下取，一次上 2～3 个产品。
- 一个顶格产品对应一个工单；子项先作为父产品素材。只有子项有独立产品页、词表与父产品重叠不大、能选出 3 个主角度时，才升格为独立工单。
- 同一产品在多个类目重复出现时只做一次，按首次出现的类目归档。

## 2. 步骤 1 · 摸清活动产品

开工先查事实，不先写词或文案。

| 必查项 | 用途 |
|---|---|
| 产品是什么 | 统一后续口径 |
| 产品形态 | 决定下载、打开、部署等动作词 |
| 目标用户与动作 | 决定人群和转化口径 |
| 核心卖点 | 后续转为角度，不直接当标题 |
| 活动钩子 | 后续转为角度或钩子，不直接当标题 |
| 竞品 | 作为对应桶的拦截词 |
| 一句话定位 | 供卷首标题使用 |
| 上线或内测状态 | 决定文案能不能写、怎么写 |

写文案前仍有关键事实不清，停止并继续查。来源只认抓回的页面原文，不拿搜索摘要冒充已读。

优先使用当前 AI 产品的联网搜索；不可用时使用用户提供的链接、页面正文或截图，再用 [`fetch_page_text.py`](../工具/fetch_page_text.py) 抓正文。活动页、产品页和官方文档都算一手来源。

产物写到当前活动 `活动细则.md` 的产品事实表。

---

## 3. 步骤 2 · 建活动细则

位置：`activities/{活动名}/物料/活动细则.md`。

复制 [`_活动细则模板.md`](../../activities/_活动细则模板.md)，完整填写 0～7 节：活动身份与类型、定位与转化动作、产品事实、用户特例与链接、命名与投放位置、稳定基线、文案与角度输入、文件与数据库索引。

活动特例只写用户给出的内容；疑似特例先问。通用流程、术语和判定规则不复制进活动细则。

---

## 4. 步骤 3 · 分人群桶

从产品价值倒推目标读者，再按“会搜什么、会读什么”拆桶。

单页活动同时满足以下两条才建桶：

1. 两类人的搜索词和阅读内容差异足够大；差异小就合并。
2. 该人群能写出 2 个回答不同读者问题的强钩子。

凑不出 2 个钩子就砍掉这个候选人群。钩子不得跨桶复制，产品事实可以复用。桶数由过闸门的人群数决定，不预设 4～7 个。

多产品活动不走本节：一个产品就是一个桶，直接进入 §5、§6。

---

## 5. 步骤 4 · 写关键词

### 5.1 圈选实体与路径

圈选对象是博文，不是人。关键词命中以下任一字段即可：

| 字段 | 内容 |
|---|---|
| 博客 landing 词 | 站外进入博文时带的词 |
| 博客描述 | 博文摘要 |
| 博客标题 | 博文标题 |
| 博客标签 | 博文标签 |

A、B 两条路径先问用户，AI 不自行选择。当前通常走 B；只有用户指定 A，或需要看 A 的后台预估曝光时才走 A。

| | A · 后台圈用户 | B · 数据平台圈博文 |
|---|---|---|
| 执行 | `run_audience.py` → `run_distribution.py` | `run_selection.py` → 人工看数量 → `run_distribution_ids.py` |
| 时点 | 固定在下午 | 随时可导 |
| 建前能读什么 | 预估圈选总数；创建后可读日均曝光预估 | 博文数、总点击、平均点击，没有曝光 |
| 达标依据 | 按 §0 的 A 路径达标线验收 | 建名单、工单并投放后，读数据库实际曝光 |

`预估圈选总数`不是曝光，只写日志供排查；不设博文数下限或上限，也不据此调整阈值。命令见 [`run_audience.md`](../../automation/docs/run_audience.md)。

### 5.2 三条铁律

1. 原子化：复合短语拆成能单独指向目标人群的词。拆到泛词就停止，伞词不单独进词表。
2. 同义多写法全保留：缩写、全称、中英文、大小写都同时投。
3. 竞品词挂进对应桶，不单独建桶。判断方法是问“搜这个词的人是在找本产品这类东西，还是找替代品”；后者才拦。

精确词可挂多个产品工单。两个桶的主角词大量重合时仍先检查是否应合并桶；确需跨桶时，在活动细则写明并约定这两桶不比 CTR。

### 5.3 输出

每个桶输出一行英文逗号分隔的关键词，下一行写“写法数 · 关键说明”；词表与对应圈选数据一起交给用户确认，不能只交词表。

```text
{A 类}: {关键词1}, {关键词2}, {关键词3}, ...
{B 类}: {关键词1}, {关键词2}, ...
```

### 5.4 后台对象

后台对象结构和 AB 权重按 §0 执行。每个资源位对应一条不同角度文案；资源数、位次、角色段和命名由 `check_batch_plan.py` 与 `naming.py` 校验。

## 6. 步骤 5 · 写文案

### 6.1 从冻结角度取文案

先按 [`选角度流程.md`](选角度流程.md) 生成并冻结 3 个主角度。写文案阶段只取现成角度，不重新选题。

- 3 个资源取 3 个角度，2 个资源取 2 个角度；同一批不重复放同一角度。
- 每个角度有首测和补验两个验证位；验证位、库存、锚点和补货按 [`想法池与1000曝光复盘流程.md`](想法池与1000曝光复盘流程.md) 执行。
- 文案从待验证想法池取，只放还没上过的文案。
- 池子不足时点名缺口，不临时写弱文案凑数。
- 一条文案使用 `文案 ID + 标题 + 摘要`；上过的文案从池里删除，读数留在复盘报告和数据库。

### 6.2 文案类型与风格

当前只启用“伪装成推荐博文”和“纯营销”两种呈现标签；定义见 [`两种文案类型.md`](../文案风格/两种文案类型.md)。

三种风格的入口和批次规则见 [`文案风格/README.md`](../文案风格/README.md)，术语定义见 [`文案风格/术语/README.md`](../文案风格/术语/README.md)。

写文案只改表达，不改冻结角度。需要同一角度占多个槽位做写法比较时，必须由用户明确指定。

### 6.3 交付前自审

每条文案必须通过 [`文案自审.md`](../文案风格/文案自审.md) 才能进入物料和 YAML。

回炉过程在对话里给用户看，格式为“改前 → 改后 → 卡在哪 + 吸睛点 / 点击理由 / 卖点判定 / 出处 / 字数”；不再生成单独自审文件。用户不逐条审批文案，只有特别中意或特别不认可时提出，其余以点击数据验证。

角度不够时先取备选角度，再回选角度流程重新生成；只有人群本身不成立时，才回 §4 重整桶。

## 7. 步骤 6 · 产出投放物料 HTML

每个桶或产品首投时生成一次物料；同一桶复盘重投不再出 HTML。

### 7.1 位置与生成

```powershell
.venv\Scripts\python.exe ad_output\工具\gen_material.py --def activities/{活动名}/配置/活动定义.yaml
```

成品位置：`activities/{活动名}/物料/投放物料/{品牌}{负责人}-{N}类投放物料.html`。生成后打开预览，交给用户确认。

### 7.2 HTML 边界

模板、占位符和 HTML 规格见 [`投放物料/README.md`](../投放物料/README.md)。纪律条只渲染全局红线和用户给的活动特例。

### 7.3 命名

`taskGroupName`只用于建或选任务组；`namePrefix`用于桶、资源、客群、工单和物料。两者在新建任务组时相同，沿用老组时可不同。所有名称由 `automation/scripts/naming.py`生成。

---

## 8. 步骤 7 · 生成 YAML 并执行

用户确认物料后，首投按 [`campaigns/README.md`](../../automation/campaigns/README.md) 生成整活动 YAML；复盘重投写 `批次/{日期}-{N}批.yaml`。

生成前把 YAML 推不出的字段列给用户确认：

- 负责人 `owner`、命名前缀 `namePrefix`、任务组 `taskGroupName`；
- 各桶子业务线 `subBusinessLine`；
- 投放起止日期和时间段；
- 当期计费价格 `taskOrder.price`。

`deliveryDate.start` 填建批当天，即复盘当天。工单建好后起始日不能改。

执行前先跑离线自检：

```powershell
.venv\Scripts\python.exe automation/scripts/check_batch_plan.py --config <批次 YAML>
```

自检通过后从 [`执行层全流程.md`](../../automation/docs/执行层全流程.md) 进入建批。每一步使用对应 `run_*.md`；正常建批直接带 `--submit`，不要再跑一遍彩排。

建完跑 `check_campaign.py` 核对对象；A 路径再用 `--only audience` 核对日均曝光预估。

## 9. 投放后取数与复盘

### 9.1 触发

自动巡检、通知格式和浏览器运维细节见 [`巡检与自动复盘.md`](../../automation/docs/巡检与自动复盘.md)。

判定只有一个触发条件：某桶累计曝光达到该桶门槛。没建下一批的桶继续提醒，直到落批。

### 9.2 指标

| 指标 | 公式 | 用途 |
|---|---|---|
| 圈选人数 | 后台显示 | 看池子大小 |
| 曝光 | 数据库 | 看系统实际展示量 |
| 展现率 | 曝光 / 圈选人数 | 看池子消化程度 |
| CTR | 点击 / 曝光 | 桶间横向比较 |
| 点击绝对数 | 数据库 | 辅助判断信号 |

### 9.3 判定与复盘

判定清单由 `judge_batch.py` 输出；首测、补验、角度状态、补货和小改统一按 [`想法池与1000曝光复盘流程.md`](想法池与1000曝光复盘流程.md) 执行。已判定小改后按 [`小改流程.md`](小改流程.md) 重写摘要。

小样本不下结论。达到桶门槛后，用累计读数判定；博文池有交集的桶不做横向 CTR 比较。

### 9.4 A 路径圈选验收

A 路径按 §0 的日均曝光门槛验收；未达标就改词重投。

```powershell
.venv\Scripts\python.exe automation/scripts/check_campaign.py --config <YAML> --only audience
```

「实际圈选博客ID数」和「预估圈选总数」只是过程读数，不替代曝光验收。B 路径没有建前曝光预估值，投放后从数据库看实际曝光。

### 9.5 数据落点

`activities/_db/投放数据.db` 是运行期唯一真相。取数、看板、活动状态和复盘记录都读数据库；YAML 只用于新批次执行与导入。

看板启动、接口和口径见 [`web/README.md`](../../web/README.md)。逐条数据、验证结论和复盘状态统一从数据库读取。

## 10. 交付验收

| 阶段 | 通过条件 |
|---|---|
| 物料前 | 产品事实、活动类型、人群、关键词、文案均齐；角度已冻结；文案已过自审 |
| YAML 前 | 用户已确认物料；负责人、任务组、子业务线、日期时间、价格均已确认 |
| 执行前 | `check_batch_plan.py` 通过，命名、权重、槽位和必填字段无错误 |
