# 想法池与门槛复盘流程

> **审批要求**：未经用户当次明确允许，不得新增或修改本文件。
> **管什么**：角度 / 文案两层想法池、桶门槛判定、槽位编排、锚点、补货和复盘输出。
> **不管什么**：活动事实查活动细则；逐条读数查数据库；文案写法查 `文案风格/`。
> **谁什么时候读**：建池、取文案、巡检判定、复盘和补货时。

> 文件名保留旧名仅用于兼容；**单资源 1,000 曝光不再是硬门槛**。

## 1. 一句话规则

每个角度固定 `首测 + 补验` 两条：首测 0 击先上补验；两条都 0 击才淘汰角度。补验用于给同角度第二次有效表达机会，角度不变，至少更换一个表达维度，可以是风格、呈现类型或钩子写法，也可以同时更换多个表达维度。已判定小改时，标题默认不动，按 `小改流程.md` 重写摘要并只输出一版。

桶总曝光达到数据库 `bucket.default_threshold_exposure` 才进入复盘；单条资源的曝光只用于说明证据强弱，不额外拦截。

## 2. 判定基础

- 博客详情页底部渠道常规 CTR：约 `0.01%～0.06%`。
- `0.10%`：有可用信号。
- `0.30%`：项目现行高线；连续复验成立后转长期单。
- **触发与判定只看桶**：该桶当前批次累计曝光达到数据库 `bucket.default_threshold_exposure`，即可复盘。
- **不设单资源额外门槛**：每条资源照常记录曝光、点击和 CTR；资源之间曝光不均、某条不足 1,000，不阻止本轮判定。
- 达标线按**该桶当次实际曝光** `ceil(曝光 × 0.3%)` 判断，不用固定击数。

## 3. 想法池结构

每个桶 / 产品当前批默认使用 **3 个主角度**；曝光不足并由用户确认把资源缩减为 2 个时，使用 **2 个主角度**。每个角度固定两个验证位；其余合格角度留在备选池，不设必须凑满的总角度数或核心库存数。

| 验证位 | 规则 |
|---|---|
| `首测` | 当前最强钩子，呈现类型和风格按表达需要选择 |
| `补验` | 与首测同角度；至少更换一个表达维度，可以是风格、呈现类型或钩子写法 |
| `备选` | 用户额外保留的候选；不占两个验证位 |

文案行在“一句话假设 / 写法”开头标清 `**首测**`、`**补验**` 或 `**备选**`。补验只要求同角度、不同写法；呈现类型和风格按角度验证需要选择，不为换风格硬凑。

**每批每个角度最多占 1 个资源位。** 首测与补验是跨批替代关系：首测 0 击后，下一批用同角度的补验替换它，不能在同一批里同时放两条同角度文案。

| 角度状态 | 含义 |
|---|---|
| 未测 | 两条文案都没上过 |
| 在测 | 至少一条在跑，或跑过但还没结论 |
| 候选 | 出过点击，或单轮信号较强 |
| 弱候选 | 连续两轮复投仍未达标，但历史上有过点击 |
| 锚点 | 多个独立批次相对稳定，建批优先保留 1 个槽位 |
| 死亡 | 首测和补验都达到门槛且都是 0 击 |

文案状态：`未投 → 在投 → 摘要小改 → 复验 → 保留 / 淘汰`。

角度死亡或当前批需要缩减、替换槽位时，从备选池选择完成证据卡、属性冻结和复核的合格角度补位；补不出合格角度时明确记录缺口，不用弱角度凑数。

新池和已启用验证位的池强制执行文案标记；旧池在下一次补货、取第二份文案或修改时迁移该角度下的文案。迁移时先按现有顺序认首测候选与补验候选；无法确认呈现类型、风格或验证位的旧文案保持空白，新写的文案补齐分类并自审，用户确认后才入池，不倒猜历史标签。

## 4. 单条文案判定

| 累计结果 | 文案动作 | 角度动作 |
|---|---|---|
| 首测 `0` 击 | 下掉，换同角度补验 | 先不判角度死亡 |
| 补验 `0` 击，且首测也 0 击 | 下掉 | 角度死亡 |
| `≥3` 击且 CTR `≥0.25%` | 原样保留一轮；每桶最多 1 条 | 进入候选 |
| `2` 击、本桶最高且 CTR `≥0.15%` | 原样保留一轮；每桶最多 1 条 | 进入候选 |
| 其余有点击但未达标 | 进入摘要小改：标题默认不动，摘要按 `小改流程.md` 重写 | 进入候选 |
| 任一条达到 `0.30%` | 原样复验 | 获得较强信号 |

0 击的稳定锚点按锚点规则先原样复验一次，不直接走补验。

**原样保留轮**只验证同一文案能否复现信号：标题、摘要均不改；如果用户明确要求改摘要或标题，则该轮属于单变量优化，不能当作严格的原样复验。

## 5. 两条文案都跑完后

| 首测 / 补验结果 | 角度结论 | 下一步 |
|---|---|---|
| 都 0 击 | 死亡 | 移入角度淘汰，补新角度 + 两条文案 |
| 首测 0、补验有点击但未达 0.30% | 候选 | 已判定小改时，从补验版按 `小改流程.md` 重写摘要 |
| 首测有点击但未达 0.30% | 候选 | 已判定小改时，从首测版按 `小改流程.md` 重写摘要；补验继续保留 |
| 至少一条 ≥ 0.30% | 强候选 | 保留最强文案，下轮原样复验 |
## 6. 稳定锚点

建议同时满足：

1. 至少两个独立批次的有效读数；
2. 两批都不是 0 击，且至少一轮 `≥ 0.20%`；
3. 累计 CTR 不低于该桶常规水平，最好 `≥ 0.10%`；
4. 原样复验没有掉回 0 击。

使用规则：

- 每桶 / 产品每批最多 1 个锚点槽位；
- 锚点单轮 0 击先原样复验；
- 复验仍 0 击，换同角度第二条；
- 两条都 0 击后撤锚；
- 连续达到 `0.30%` 才转长期单。

## 7. 每批槽位

- **3 资源**：有锚点时 = 1 个锚点 + 2 个新角度；无锚点时 = 3 个新角度。
- **2 资源**：有锚点时 = 1 个锚点 + 1 个新角度；无锚点时 = 2 个新角度。
- 默认一槽一个角度；用户明确要测写法时，才让同一角度占多个槽位。

取文案优先级：

`稳定锚点 > 已有点击但未复验 > 从未上过的角度 > 摘要小改`

## 8. 摘要小改

小改是否触发由复盘判定决定；一旦决定小改，不再读取点击数和 CTR 决定“改什么”。具体执行见 [`小改流程.md`](小改流程.md)。

- 标题默认保持原文不动；用户当次明确要求除外；
- 摘要可以整句重写，不要求保留原句结构；
- 角度、点击理由、文案风格、事实和证据来源不变；
- 只输出一条默认新摘要，不再生成四选一，也不把换风格混入小改；
- 新摘要必须产生实质变化，不能只改标点、时间词或公文式措辞；
- 写成后交给现有 `文案自审.md` 做最终检查，自审不参与决定怎么改。

| 小改版结果 | 下一步 |
|---|---|
| 达到 `0.30%` | 原样复验，进入候选 / 锚点路径 |
| 有点击但未达标 | 保留最佳有击版本；是否继续由现有复验 / 角度状态规则判定，不再生成四选一 |
| `0` 击 | 撤销这次小改，回跑此前有点击的原始版本一次；仍 0 击则换未投补验或其他角度 |

原始有击版必须冻结留档。一次小改失败不能直接判角度死亡。

后台不能修改已上线资源；摘要小改复投 = 新建资源 + 新工单。

## 9. 批次级塌陷

先比较同桶上一批。以下同时成立时，三条原样复跑：

- 本批 CTR 掉到上一批的 1/3 以下；
- 上一批出点击的槽位本批全 0；
- 同批其他桶正常；
- 按上一批各槽 CTR 计算，本批实得 ≤ 1% 分位。

复跑正常 → 回到单条判定；复跑仍塌 → 记批次异常。

## 10. 长期单

连续验证达到 `0.30%` 后：

1. 写 `调整/{日期}-{桶}长期单.yaml`：
   `abTest: false`、1 条资源、`label: 对照组`、`nameSuffix: '-长投'`、复用现成名单。
2. 跑 `check_batch_plan.py`。
3. 跑 `run_taskorder.py --submit`，随后 `check_campaign.py --only order`。
4. 新单跑起来后，下线该桶老工单。

长期单掉回 `0.30%` 以下一个量级，撤销资格并回到普通测试轮换。

## 11. 库存与归档

- 不设固定角度总数或固定文案库存上限。
- 当前批每个角度至少准备首测文案；首测 0 击后，再使用该角度的补验文案。
- 当前批无法凑齐 2～3 个合格角度，或某个角度需要补验却没有可用文案时，记录缺口并从备选池补角度或补文案。
- 死亡角度不补文案，直接换新角度。
- 已投文案从池子删除；读数留在复盘报告和数据库。

归档：

- 想法池：`activities/{活动}/物料/待验证想法/`
- 死亡角度：`activities/{活动}/物料/角度淘汰/`
- 复盘：`activities/{活动}/物料/复盘/复盘-{桶}.md`
- 逐条历史：`activities/_db/投放数据.db`
- 本轮动作：数据库 `review` / `review_resource`
- 判定清单：运行 `judge_batch.py --brief` 查看；到期项写入数据库 `review.status='due'`

## 12. 每轮复盘顺序

1. 刷新数据；当前桶累计曝光达到数据库 `bucket.default_threshold_exposure` 就判，不再等每条资源满 1,000。
2. 先过批次级塌陷闸。
3. 逐条判定文案，再汇总角度。
4. 首测 0 击取同角度补验；补验至少更换一个表达维度，可以是风格、呈现类型或钩子写法，两条都 0 击才淘汰角度。
5. 已判定小改时，按 `小改流程.md` 只重写摘要，标题默认不动，不再生成四选一。
6. 更新锚点、弱候选和备选角度缺口。
7. 从池子取下一轮文案；新文案仍走自审并经用户确认后入池。
8. 用户确认后建批，并给出待下线老工单。
9. 回写复盘报告、想法池、复盘动作和执行记录；指标与判定结果以数据库为准。

## 13. 每轮必须交代

1. 待下线老工单：桶 + 任务 ID，先上新后下旧。
2. 想法池状态：死亡 / 候选 / 锚点 / 缺货。
3. 下一步一句话：下一批验证什么。

## 14. 边界

- 脚本与人工复盘统一以数据库 `bucket.default_threshold_exposure` 为唯一触发和判定依据；**不得额外加单资源 1,000 曝光门槛**。资源曝光只用于解释证据强弱。
- `文案风格/文案自审.md` 是审批件，未经用户允许不改。
- 跨活动结论必须经过多轮验证，并通过 `文案风格/文案自审.md` 后才作为通用写法使用。
