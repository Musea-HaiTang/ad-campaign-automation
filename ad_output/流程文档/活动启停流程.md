# 活动启停流程

> **管什么**：新活动启动、活动收尾、恢复跟进和生命周期字段口径。
> **不管什么**：新建下一批 → `CSDN广告投放自动化流程.md`；后台停投 → 人工确认后按后台任务 ID 操作；复盘正文 → `automation/docs/复盘会话格式.md`。
> **谁什么时候读**：活动开始、结束、恢复或排查看板/巡检为什么跳过活动时。

## 1. 唯一状态源

活动运行状态以数据库 `activities/_db/投放数据.db` 的 `activity` 表为准：

| 字段 | 作用 |
|---|---|
| `status` | `active` = 项目内继续跟进；`ended` = 项目内已收尾 |
| `started_on` | 活动开始日，建立活动后不再随批次变化 |
| `ended_on` | 用户确认的收尾日；`active` 时必须为空 |

以下位置不再是运行状态源：

- `campaign.status` / `campaign.endedAt` 只用于活动首次导入。
- `已结束.md` 不再读取，也不再需要创建。
- 后台工单的“下线 / 进行中”只表示 CSDN 投放状态，不决定项目是否复盘。

## 2. 启动新活动

1. 用户给出活动链接，并明确要求启动。
2. 按 [`CSDN广告投放自动化流程.md`](CSDN广告投放自动化流程.md) 完成产品、人群、文案和物料。
3. 用户确认物料和整活动 YAML。
4. 执行层首次运行 `run_ads.py` / `run_taskorder.py` 时，把活动写入数据库。
5. 首次写库时使用整活动 YAML 的 `campaign.status` 和投放开始日；此后以数据库为准。
6. 看板、取数和自动巡检从数据库中看到该活动。

“启动成功”的判据：

- 数据库 `activity.status='active'`；
- 后台对象已创建并通过回读；
- 工单已提交并审核上线；
- 看板能看到该活动；
- 自动巡检能读到该活动的当前批。

## 3. 建下一批

同一活动复盘后继续投放：

- 不修改活动生命周期；
- 不新建任务组；
- 在 `activities/{活动}/批次/` 建新的执行 YAML；
- 新工单上线后再下线老工单。

## 4. 收尾活动

### 4.1 先区分两件事

- **项目内收尾**：不再建批、不再补文案、不再自动复盘。
- **后台停投**：把 CSDN 后台仍在进行中的任务工单下线。

项目内收尾不会自动下线后台工单。

### 4.2 修改数据库状态

先向用户确认收尾日，然后执行：

```powershell
.venv\Scripts\python.exe automation/scripts/activity_state.py `
  end "腾讯云产品-hang" --on 2026-10-28
```

结果：

- `activity.status` 改为 `ended`；
- `activity.ended_on` 写入用户确认的日期；
- 看板和新一轮巡检立即把它视为已收尾；
- 收尾日之后保留 2 天自动补数窗口，用于回收后台延迟数据；
- 补数窗口结束后不再自动刷新或复盘。

### 4.3 后台停投

如果用户要求立即停止投放：

1. 从数据库列出该活动仍在进行中的桶和任务 ID。
2. 把任务 ID 清单交给用户。
3. 用户明确授权后再操作 CSDN 后台下线。
4. 重新取数，确认任务状态已变化。

## 5. 恢复活动

用户明确要求恢复项目内跟进时：

```powershell
.venv\Scripts\python.exe automation/scripts/activity_state.py `
  start "腾讯云产品-hang"
```

结果：

- `status` 改回 `active`；
- `ended_on` 清空；
- 看板和巡检重新纳入该活动。

这只恢复项目内跟进。后台工单若已下线，需要按新批流程重新投放。

## 6. 查看当前状态

```powershell
.venv\Scripts\python.exe automation/scripts/activity_state.py list
```

输出包含每个活动的：

- `activity_key`
- 进行中 / 已收尾
- 开始日
- 收尾日

## 7. 禁止项

- 不用修改旧批次 YAML 的方式启停活动。
- 不根据投放截止日自动推断收尾。
- 不把项目内收尾说成后台已停投。
- 不因为收尾删除历史批次、指标、任务 ID 或复盘。
- 不在新批审核通过前先下线老批。
