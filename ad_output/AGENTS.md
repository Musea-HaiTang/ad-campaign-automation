## 工具层纪律（只有这一层才定的规矩）

- **数据/代码分离**：活动内容（分桶 / 关键词 / 文案）写在「活动定义 YAML」里，生成器（`工具/*.py`）不含任何活动内容。改内容 = 改活动定义 YAML 后重跑生成器。
- **复盘结论和经验总结直接查询数据库**，不再维护独立的数据台账或数据经验文档。
- **名字不在生成器里拼**：桶名 / 资源名 / 工单名 / 物料文件名统一问 `../automation/scripts/naming.py` 要（命名规则的唯一实现，见流程文档 §7.3）。
- **纪律只有两条来源**：全局红线（忌「翻墙」字样，生成器固定注入）+ **用户给的活动特例**（`活动定义.yaml` 的 `activity.ruleText`，可空）。AI 不自行提炼纪律（流程文档 §0 / §3）。
- **产出即验证**：`gen_yaml.py` 写完会用 `../automation/scripts/campaign.py` 的契约校验器自检，不合契约（缺必填 / 字段名打错）直接报错、不落盘。
- ⛔ **出完物料 HTML 必须停下、等用户确认/改完**，才生成整活动 YAML；不得自行继续到执行层（完整门控见流程文档 §8）。
- ⛔ **生成 YAML 前必须问用户当期「计费价格」**（2026-09-22 起不再固定数值，历史 20 / 30 都不套用）——问清再生成；
  字段与待确认清单见 `../automation/campaigns/README.md` 的「生成前确认」。
